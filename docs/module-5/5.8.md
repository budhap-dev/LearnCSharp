## The idea

A **graph** is nodes joined by edges — the structure with no shape rules at all. A tree
([5.7](5.7.md)) is merely a graph with no cycles and one route between any two nodes.

| Term | Meaning | Example |
|---|---|---|
| vertex / node | a thing | a city, a person, a web page |
| edge | a connection | a road, a friendship, a link |
| directed | edges go one way | "follows" on social media |
| undirected | edges go both ways | friendship, a two-way road |
| weighted | each edge has a cost | distance, time, price |

Maps, social networks, the web, dependency graphs, game maps (project
[7.3](../module-7/7.3.md)) — all graphs.

## Storing one

**Adjacency list** — a dictionary from node to neighbours. The default choice:

```csharp
private readonly Dictionary<string, List<string>> _adjacency = new();

public void AddEdge(string from, string to)
{
    _adjacency[from].Add(to);
    _adjacency[to].Add(from);       // undirected: record it both ways
}
```

**Adjacency matrix** — a 2D grid of booleans. O(1) edge lookup, O(V²) memory; sensible only
when nearly everything connects to nearly everything.

The lesson's map:

```
A ---- B
|    / |
|  /   |
C ---- D ---- E
              |
              F
```

## Breadth-first search — a Queue explores in rings

Visit the start, then everything one step away, then two steps away…

```csharp
public List<string> BreadthFirst(string start)
{
    List<string> order = new();
    HashSet<string> seen = [start];        // mark when ENQUEUED, not when visited
    Queue<string> pending = new([start]);

    while (pending.Count > 0)
    {
        string node = pending.Dequeue();
        order.Add(node);

        foreach (string neighbour in Neighbours(node))
            if (seen.Add(neighbour))       // Add returns false if already seen (3.2!)
                pending.Enqueue(neighbour);
    }

    return order;
}
```

Three earlier lessons assemble here: the `Queue` from [5.6](5.6.md), `HashSet.Add`'s bool from
[3.2](../module-3/3.2.md), and the ring-by-ring order is why BFS finds the **shortest path in
an unweighted graph** — you cannot reach ring 3 before exhausting ring 2.

The `seen` set is what stops cycles looping forever — the one hazard trees never had.

### Recovering the actual path

Record how each node was reached, then walk the breadcrumbs backwards:

```csharp
Dictionary<string, string?> cameFrom = new() { [start] = null };
// during BFS:  cameFrom[neighbour] = node;
// afterwards:  walk from end back to null, then Reverse()
```

`A → F` on the map above: `A -> B -> D -> E -> F` — four hops, provably minimal.

## Depth-first search — a Stack charges down one path

Go as deep as possible, backtrack, try the next branch. Two spellings, same algorithm:

```csharp
// recursion - the call stack IS the stack (5.4)
private void Visit(string node, HashSet<string> seen, List<string> order)
{
    if (!seen.Add(node)) return;
    order.Add(node);
    foreach (string neighbour in Neighbours(node))
        Visit(neighbour, seen, order);
}

// or explicitly: same logic, Stack<string> instead of recursion, no depth limit
```

| | BFS | DFS |
|---|---|---|
| Uses | Queue | Stack / recursion |
| Explores | in rings | down one path first |
| Finds shortest path (unweighted) | **yes** | no |
| Memory | wide frontiers can be large | one path deep |
| Natural for | shortest routes, "degrees of separation" | mazes, cycle detection, topological sort |

Both are **O(V + E)** — every node and edge examined once.

## Weighted graphs: Dijkstra's algorithm

When edges have costs, fewest hops is no longer cheapest. Dijkstra fixes that with one change:
the plain queue becomes a **priority queue** ([3.3](../module-3/3.3.md)) that always hands
back the cheapest-known unexplored node.

```csharp
PriorityQueue<string, int> pending = new();
Dictionary<string, int> distance = /* all int.MaxValue, start = 0 */;

while (pending.Count > 0)
{
    string node = pending.Dequeue();               // cheapest so far
    if (!settled.Add(node)) continue;

    foreach ((string to, int weight) in _adjacency[node])
    {
        int candidate = distance[node] + weight;
        if (candidate < distance[to])              // found a cheaper way in - "relax"
        {
            distance[to] = candidate;
            cameFrom[to] = node;
            pending.Enqueue(to, candidate);
        }
    }
}
```

The lesson's weighted map makes the contrast concrete:

```
fewest hops A -> F:   A -> B -> D -> E -> F        (4 hops, cost 14)
cheapest   A -> F:    A -> C -> B -> D -> E -> F   (5 hops, cost 13)
```

Dijkstra happily takes *more* hops to spend *less* — which is your satnav accepting three
extra junctions to avoid the toll road. One caveat: Dijkstra assumes **no negative weights**.

Complexity with a priority queue: O((V + E) log V).

## Connectivity

BFS from a node reaches exactly its **component**. Repeat from every unvisited node and count
components — the lesson adds an island node `Z` and finds 2. "Can I reach X?" is just "did BFS
touch X?".

## Common mistakes

| Mistake | Result |
|---|---|
| Marking seen on *dequeue* instead of *enqueue* | Nodes queued twice; wasted work or wrong paths |
| No `seen` set at all | Infinite loop on the first cycle |
| DFS for shortest path | A path, not the shortest one |
| Forgetting the reverse edge on undirected graphs | Half the map unreachable |
| Dijkstra with negative weights | Silently wrong answers |
