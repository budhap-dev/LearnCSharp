## Vocabulary first

| Term | Meaning |
|---|---|
| root | the single node at the top |
| parent / child | directly above / below |
| leaf | a node with no children |
| subtree | any node together with everything below it |
| height | longest path from root to a leaf |
| binary tree | every node has at most two children |

A tree node is the [5.5](5.5.md) node with a second pointer:

```csharp
public class TreeNode
{
    public int Value { get; set; }
    public TreeNode? Left { get; set; }
    public TreeNode? Right { get; set; }
}
```

## The binary search tree rule

**Everything smaller lives in the left subtree; everything larger in the right.** At every
node, without exception.

Inserting `50, 30, 70, 20, 40, 60, 80, 35` grows this:

```
        50
    30      70
  20  40  60  80
     35
```

The rule has two glorious consequences:

- searching is binary search ([5.2](5.2.md)) **in structure form** — each comparison discards
  half the tree;
- an in-order walk visits values **in sorted order, for free**.

## Insert and search — follow the rule down

```csharp
private static TreeNode Insert(TreeNode? node, int value)
{
    if (node is null) return new TreeNode(value);        // found the empty spot

    if (value < node.Value) node.Left = Insert(node.Left, value);
    else node.Right = Insert(node.Right, value);

    return node;
}
```

Recursion matching recursive data, exactly as promised in [5.4](5.4.md). Search is the same
walk without the writing:

```
searching for 35:
step 1: at 50 -> 35 is smaller, go left
step 2: at 30 -> 35 is bigger, go right
step 3: at 40 -> 35 is smaller, go left
step 4: at 35 -> FOUND
```

Both are **O(height)** — which is the whole story of this lesson, as you will see.

Handy corollaries: the minimum is the leftmost node; the maximum is the rightmost.

## The four traversals

Three orders of "visit me vs my children", plus one that needs a queue:

| Traversal | Order | Produces / used for |
|---|---|---|
| **in-order** | left, node, right | **sorted output** |
| **pre-order** | node, left, right | copying or serialising a tree |
| **post-order** | left, right, node | deleting safely (children first); evaluating expressions |
| **level-order** | row by row | breadth-first — uses a **Queue** ([5.6](5.6.md)), not recursion |

On the tree above:

```
in-order:    20, 30, 35, 40, 50, 60, 70, 80     <- sorted!
pre-order:   50, 30, 20, 40, 35, 70, 60, 80
post-order:  20, 35, 40, 30, 60, 80, 70, 50
level-order: 50, 30, 70, 20, 40, 60, 80, 35
```

Each recursive traversal is three lines — the order of those lines *is* the definition:

```csharp
private static void InOrder(TreeNode? node, List<int> result)
{
    if (node is null) return;
    InOrder(node.Left, result);
    result.Add(node.Value);
    InOrder(node.Right, result);
}
```

## Deleting — three cases

1. **Leaf** — just remove it.
2. **One child** — promote the child into its place.
3. **Two children** — replace the node's value with its **in-order successor** (the smallest
   value in the right subtree), then delete that successor. The BST rule survives intact.

Case 3 is the one exam questions and interviews probe; the lesson runs all three.

## Balance is everything

Insert `10, 20, 30, 40, 50, 60, 70` — sorted input — and the "tree" grows like this:

```
10
  20
    30
      40
        ...
```

Every node went right. Height 7 for 7 nodes: **a linked list wearing a tree costume**, and
search is back to O(n). The same seven values inserted in a shuffled order give height 3.

| | Balanced | Degenerate |
|---|---|---|
| Height for n nodes | ~log₂ n | n |
| Search 1,000,000 nodes | ~20 comparisons | up to 1,000,000 |

Real systems therefore use **self-balancing** trees (AVL, red-black) that rotate nodes on
insert to keep height logarithmic. You do not need to implement one — but you must know *why*
they exist, and that .NET's are:

```csharp
SortedSet<int>              // a red-black tree
SortedDictionary<K, V>      // likewise - sorted keys, O(log n) everything
```

versus `Dictionary`'s O(1)-but-unordered hashing ([3.2](../module-3/3.2.md), [5.9](5.9.md)).
Choose by whether you need the order.

## Expression trees — a second life for traversals

`(3 + 4) * 5` as a tree: operators are branches, numbers are leaves.

```
      *
    +   5
  3   4
```

- in-order walk → `(3 + 4) * 5` — infix, the notation you write
- post-order walk → `3 4 + 5 *` — **exactly the RPN** the [5.6](5.6.md) stack evaluated
- post-order evaluation → 35 — children before parent, so operands exist before the operator

Compilers parse your source into exactly such trees. The two lessons just shook hands.

## Where trees appear

File systems ([5.4](5.4.md)'s folders) · HTML/XML DOM · database indexes (B-trees) ·
compilers' syntax trees · game decision trees.

## Common mistakes

| Mistake | Result |
|---|---|
| Breaking the BST rule on one insert | Search silently wrong forever after |
| In-order confused with pre-order | Unsorted output where sorted was assumed |
| Deleting a two-child node by promotion alone | Rule violated — use the successor |
| Inserting sorted data into a plain BST | Degenerate O(n) tree |
| Recursing on a degenerate tree | Deep recursion — the [5.4](5.4.md) overflow risk |
