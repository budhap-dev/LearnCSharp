## The idea

[3.3](../module-3/3.3.md) *used* `Stack<T>` and `Queue<T>`. This lesson builds both — twice
over — because the implementations teach two lasting techniques: **amortised growth** and the
**circular buffer**.

## A stack on an array

Push and pop both work at the end, so both are O(1):

```csharp
public class ArrayStack<T>
{
    private T[] _items;
    public int Count { get; private set; }

    public void Push(T item)
    {
        if (Count == _items.Length)
            Array.Resize(ref _items, _items.Length * 2);    // double when full

        _items[Count] = item;
        Count++;
    }

    public T Pop()
    {
        if (Count == 0) throw new InvalidOperationException("The stack is empty.");
        Count--;
        T item = _items[Count];
        _items[Count] = default!;        // release the reference for the GC (4.8)
        return item;
    }
}
```

The doubling is the same strategy `List<T>` uses ([3.1](../module-3/3.1.md)) — occasional O(n)
copies, O(1) amortised. Note the small courtesy of clearing the popped slot so the GC can
reclaim what it points to.

## A stack on a linked list

```csharp
public void Push(T item)
{
    _top = new StackNode(item, _top);    // new node points at the old top
    Count++;
}

public T Pop()
{
    T value = _top.Value;
    _top = _top.Below;
    Count--;
    return value;
}
```

No capacity, no resizing, no wasted slots — every operation is two pointer moves. This *is*
`AddFirst`/`RemoveFirst` from [5.5](5.5.md) wearing a different interface: **a stack is a
linked list you only touch at one end.**

## The queue problem — and the circular fix

A naive array queue dequeues from index 0 and shuffles everything left: O(n) per dequeue. The
fix is to move the *indices* instead of the *data*:

```csharp
public class CircularQueue<T>
{
    private readonly T[] _items;
    private int _head;              // where to read
    private int _tail;              // where to write

    public void Enqueue(T item)
    {
        if (IsFull) throw new InvalidOperationException("The queue is full.");
        _items[_tail] = item;
        _tail = (_tail + 1) % _items.Length;    // wrap past the end back to 0
        Count++;
    }

    public T Dequeue()
    {
        if (IsEmpty) throw new InvalidOperationException("The queue is empty.");
        T item = _items[_head];
        _items[_head] = default!;
        _head = (_head + 1) % _items.Length;
        Count--;
        return item;
    }
}
```

Watch the lesson's trace — after two dequeues and two enqueues the contents *wrap around* the
physical array:

```
after 3 enqueues:   front [Ada, Ben, Cara] back   (array: Ada, Ben, Cara, _,  head=0, tail=3)
dequeue x2:         front [Cara] back             (array: _, _, Cara, _,      head=2, tail=3)
enqueue Dev, Eve:   front [Cara, Dev, Eve] back   (array: Eve, _, Cara, Dev,  head=2, tail=1)
```

`Eve` physically sits at index 0 while logically last — the `%` from [1.4](../module-1/1.4.md)
("wrap around a circle of size n") doing precisely what it promised. Both operations are O(1),
nothing ever shuffles. Ring buffers like this run keyboard input, audio streaming and network
buffers.

Note `Count` is tracked separately — `head == tail` alone cannot distinguish empty from full.

## The implementations put to work

**Reverse Polish Notation** — operands push; an operator pops two, computes, pushes back:

```
"5 1 2 + 4 * + 3 -"  ->  14
```

```csharp
int right = values.Pop();       // the SECOND operand comes off first
int left = values.Pop();
values.Push(ApplyOperator(token, left, right));
```

No brackets, no precedence rules — the ordering *is* the notation. This is how calculators and
bytecode interpreters (including the IL your C# compiles to — [1.1](../module-1/1.1.md))
evaluate expressions.

**Decimal to binary** — repeated division yields bits backwards; a stack un-reverses them:

```csharp
while (number > 0) { bits.Push(number % 2); number /= 2; }
while (!bits.IsEmpty) result.Append(bits.Pop());
```

**Round-robin scheduling** — a queue of jobs, each takes a turn, unfinished jobs rejoin the
back. The lesson runs three tasks to completion; real operating systems schedule threads with
the same shape.

## Common mistakes

| Mistake | Result |
|---|---|
| Forgetting `%` on head/tail advance | Index out of range at the wrap |
| Using `head == tail` for empty *and* full | The two states are indistinguishable — track Count |
| Popping operands in the wrong order | `5 - 3` becomes `3 - 5` in RPN |
| Not clearing popped/dequeued slots | Stale references delay garbage collection |
