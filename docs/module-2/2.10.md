## What every type inherits

Because everything derives from `object` ([2.5](2.5.md)), every type already has:

| Member | Default behaviour | Should you override it? |
|---|---|---|
| `ToString()` | prints the type name | **almost always** |
| `Equals(object)` | reference identity | for value-like types |
| `GetHashCode()` | identity-based | **always with `Equals`** |
| `GetType()` | runtime type | no |

## `ToString`

```csharp
public override string ToString() => $"({X}, {Y})";
```

Without it, printing an object gives you `LearnCSharp.Lessons.Oop.Vector` — useless in a debugger
and useless in a log. String interpolation picks it up automatically, so this one override pays
for itself immediately.

## `Equals`

```csharp
public override bool Equals(object? obj) =>
    obj is Vector other && X.Equals(other.X) && Y.Equals(other.Y);
```

Check the type and compare the contents. Note `obj is Vector other` handles both the null case
and the type check in one step.

## `GetHashCode` — and why it must match

```csharp
public override int GetHashCode() => HashCode.Combine(X, Y);
```

**The contract:** if `a.Equals(b)` is true, then `a.GetHashCode() == b.GetHashCode()` *must*
also be true.

Break it and dictionaries silently lose your objects. A `Dictionary` finds a bucket from the
hash code and only *then* checks equality — so if two equal objects hash differently, they land
in different buckets and never meet.

`HashCode.Combine(...)` does the hard part properly. Use it rather than inventing your own.

> Rule: **always override `Equals` and `GetHashCode` together.** The compiler warns if you do
> not. This is also exactly why dictionary keys must be immutable ([5.9](../module-5/5.9.md)).

## Operator overloading

```csharp
public static Vector operator +(Vector left, Vector right)
    => new(left.X + right.X, left.Y + right.Y);

public static Vector operator *(Vector v, double scale) => new(v.X * scale, v.Y * scale);
public static Vector operator -(Vector v) => new(-v.X, -v.Y);     // unary
```

```csharp
v1 + v2      // (4, 5)
v1 * 2       // (6, 8)
-v1          // (-3, -4)
```

Operators must be `public static`. Some come in **required pairs**: `==` with `!=`, `<` with
`>`, `<=` with `>=`.

```csharp
public static bool operator ==(Vector? left, Vector? right) =>
    left is null ? right is null : left.Equals(right);

public static bool operator !=(Vector? left, Vector? right) => !(left == right);
```

> Only overload an operator when the meaning is **obvious**. `+` on two vectors is clear.
> `+` on two `Customer` objects is a riddle. When in doubt, write a named method.

## Conversion operators

```csharp
// implicit: cannot fail, no information lost
public static implicit operator Vector((int x, int y) t) => new(t.x, t.y);

// explicit: might lose something, so the caller must ask
public static explicit operator (int, int)(Vector v) => ((int)v.X, (int)v.Y);
```

```csharp
Vector v = (5, 12);                      // implicit - just works
(int x, int y) t = ((int, int))v;        // explicit - cast required
```

The rule mirrors the built-in types: widening is implicit, narrowing needs a cast
([1.10](../module-1/1.10.md)).

## `IComparable<T>` for sorting

```csharp
public int CompareTo(Vector? other) => other is null ? 1 : Length.CompareTo(other.Length);
```

Now `List.Sort()` and `Array.Sort()` know what to do with your type.

## Records do all of this for you

Everything on this page is generated automatically for a `record` ([2.9](2.9.md)) — which is
exactly why records are usually the better choice for pure data. Learn these overrides so you
understand what a record generates, and so you can do it by hand when you need a class.

## Common mistakes

| Mistake | Result |
|---|---|
| Overriding `Equals` but not `GetHashCode` | Objects vanish inside dictionaries and sets |
| Overriding `==` but not `!=` | Compile error |
| Hash code built from mutable fields | The object gets lost when the field changes |
| `Equals(Vector other)` only | That is an overload, not an override — the base still runs |
| Overloading operators with unclear meaning | Unreadable code |

## Exercises

1. Write a `Fraction` class with `+`, `-`, `*`, `/`, `==`, `ToString` and proper equality.
2. Deliberately override `Equals` without `GetHashCode`, put the objects in a `HashSet`, and
   watch duplicates survive.
3. Add `IComparable<Fraction>` and sort a list of fractions.
4. Rewrite `Fraction` as a `record struct`. How much code disappears?
