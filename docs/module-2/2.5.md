## The idea

Inheritance builds a new class on top of an existing one. The child gets everything the parent
has — and adds to it.

```csharp
public class Animal
{
    protected int _energy = 100;

    public Animal(string name, int age) { Name = name; Age = age; }

    public string Name { get; }
    public int Age { get; }

    public string Describe() => $"{Name}, aged {Age}";
}

public class Dog : Animal              // "Dog IS AN Animal"
{
    public Dog(string name, int age, string breed) : base(name, age)
    {
        Breed = breed;
    }

    public string Breed { get; }

    public string Fetch()
    {
        _energy -= 10;                 // allowed: _energy is protected
        return $"{Name} fetches the ball.";
    }
}
```

`rex.Describe()` works even though `Dog` never defines it. It was inherited.

## The test: IS-A

Only use inheritance when the child genuinely **is a kind of** the parent.

| Sentence | Inheritance? |
|---|---|
| A Dog **is an** Animal | ✅ yes |
| A Square **is a** Rectangle | ⚠️ mathematically yes, in code often no — see [2.13](2.13.md) |
| A Car **is an** Engine | ❌ no — a Car **has an** Engine ([2.12](2.12.md)) |
| An Order **is a** List | ❌ no — an Order **has** items |

If you catch yourself inheriting to reuse a bit of code, stop. That is what composition is for.

## Constructors run base-first

```csharp
public Dog(string name, int age, string breed) : base(name, age)
```

`: base(...)` passes arguments up to `Animal`'s constructor, which runs **first**. The parent
must be fully built before the child can add to it. Run the lesson and watch the order print.

If the parent has a parameterless constructor, `: base()` is implied and you can omit it.

## `protected`

| Modifier | Visible to |
|---|---|
| `private` | this class only |
| `protected` | this class **and anything inheriting from it** |
| `public` | everyone |

`protected` is the modifier inheritance exists for: `Dog.Fetch()` can touch `_energy` because
`Animal` marked it protected. Outside code still cannot.

## Everything inherits from `object`

```csharp
rex is Animal              // true
rex is object              // true
typeof(Dog).BaseType       // Animal
typeof(Animal).BaseType    // object
```

Every type in .NET, including `int`, ultimately derives from `object`. That is why every value
has `ToString()`, `Equals()` and `GetHashCode()` — see [2.10](2.10.md).

## Upcasting and downcasting

**Up** the hierarchy is always safe and automatic:

```csharp
Animal asAnimal = rex;     // a Dog is definitely an Animal
```

**Down** might fail, so it must be checked:

```csharp
if (asAnimal is Dog backToDog)     // safe: pattern match
    backToDog.Fetch();

Dog? maybe = asAnimal as Dog;      // safe: null if it is not a Dog

Dog wrong = (Dog)someCat;          // throws InvalidCastException
```

> Prefer the pattern form `is Dog dog`. It tests and gives you the typed variable in one step.

## `sealed`

```csharp
public sealed class Puppy : Dog { }    // nothing may inherit from Puppy
```

Sealing says "this is the end of the line". It prevents surprises and lets the compiler
optimise. `string` is sealed, which is exactly why extension methods exist ([4.4](../module-4/4.4.md)).

## C# has single inheritance only

A class may have **exactly one** base class. This avoids the "diamond problem" that plagues
C++. To mix in several capabilities, use interfaces ([2.7](2.7.md)) or composition
([2.11](2.11.md)).

## Common mistakes

| Mistake | Fix |
|---|---|
| Inheriting to reuse code, not because IS-A holds | Use composition |
| Deep hierarchies (4+ levels) | Flatten; prefer interfaces |
| Making fields `public` so children can reach them | Use `protected` |
| Hard-casting down without checking | Use `is` or `as` |
| Expecting multiple base classes | Not allowed — use interfaces |
