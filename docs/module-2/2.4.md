## The idea

**Encapsulation** means: an object's data is private, and the only way to change it is through
methods that enforce the rules. The object protects its own correctness.

```diagram
encapsulation
```

## Why a public field is dangerous

```csharp
public class BadAccount
{
    public decimal Balance;      // anyone can write anything
}

bad.Balance = -5000;             // nothing stops this
```

The object is now in a state that should be impossible, and nothing in the class can prevent it
or even notice.

## The same thing done properly

```csharp
public class BankAccount
{
    private decimal _balance;                    // the real state, hidden

    public BankAccount(string owner, decimal opening)
    {
        Owner = owner;
        _balance = opening;
    }

    public string Owner { get; }

    public decimal Balance => _balance;          // read from outside, write only inside

    public void Deposit(decimal amount)
    {
        if (amount <= 0)
            throw new ArgumentOutOfRangeException(nameof(amount), "Deposit must be positive.");

        _balance += amount;
    }

    public bool Withdraw(decimal amount)
    {
        if (amount <= 0 || amount > _balance) return false;
        _balance -= amount;
        return true;
    }
}
```

Now `account.Balance = 1_000_000;` will not compile, and every change goes through a rule.

> Note the deliberate difference: `Deposit` **throws** because a negative deposit is a *bug in
> the calling code*, while `Withdraw` **returns false** because "not enough money" is a normal,
> expected outcome. Choosing between these correctly is a real design skill.

## Kinds of property

```csharp
// 1. Auto-property
public string Author { get; set; }

// 2. Read-only from outside
public decimal Balance => _balance;

// 3. Computed - no stored value at all
public bool IsOverdrawn => _balance < 0;
public string Summary => $"{Owner}: {_balance:F2}";

// 4. Full property with validation
public int Health
{
    get => _health;
    set => _health = Math.Clamp(value, 0, 100);   // 'value' is the incoming assignment
}

// 5. Different access for get and set
public string Name { get; private set; }

// 6. init-only: set at creation, then frozen
public int Port { get; init; }

// 7. required: the compiler insists you set it
public required string Host { get; init; }
```

`value` is a keyword available inside any setter — it holds whatever was assigned.

## Access modifiers

| Modifier | Visible to |
|---|---|
| `public` | everyone |
| `private` | this class only — **the default for members** |
| `protected` | this class and anything inheriting from it |
| `internal` | anything in this project/assembly — **the default for classes** |
| `protected internal` | either of the two above |
| `private protected` | inheritors, but only inside this assembly |

**Default to `private`.** Widen only when something genuinely needs to be seen from outside.

## Properties vs fields vs methods

| Use a… | When |
|---|---|
| private field | storing internal state |
| property | exposing a value; cheap to compute; no side effects |
| method | it does work, takes arguments, or could fail |

A property should feel like data. `account.Balance` is fine; `account.RecalculateInterest()`
should be a method, because it does something.

## Read-only collections

Exposing a `List<T>` lets outsiders add to it behind your back:

```csharp
public List<string> Items { get; } = new();       // caller can do Items.Add(...)

private readonly List<string> _items = new();      // better
public IReadOnlyList<string> Items => _items;      // look, but do not touch
public void AddItem(string item) { /* validate */ _items.Add(item); }
```

## Common mistakes

| Mistake | Fix |
|---|---|
| Public fields everywhere | Make them private, expose properties |
| A setter with no validation where validation is needed | Use a full property |
| `public int Health { get; set; }` then clamping in ten call sites | Clamp once, in the setter |
| Exposing a mutable `List<T>` | Expose `IReadOnlyList<T>` |
| A property that throws or takes a second to run | Make it a method |

## Exercises

1. Take your `Rectangle` from 2.2 and make `Width`/`Height` refuse negative values.
2. Write a `Thermostat` class with a `Target` property clamped to 5–30 °C, and a computed
   `IsHeating` property.
3. Write a `Password` class that stores a value but only exposes `Length` and
   `IsStrongEnough` — never the password itself.
4. Write an `Inventory` class holding a private `List<string>`, exposing `IReadOnlyList<string>`
   plus `Add`, `Remove` and a `Count` property, with a maximum capacity.
