## The idea

*Polymorphism* means "many forms". One variable, declared as one type, behaving differently
depending on what it actually holds.

```csharp
Shape[] shapes = [new Circle(3), new Rectangle(4, 5), new Square(6)];

foreach (Shape shape in shapes)
    Console.WriteLine(shape.Area());     // each runs ITS OWN Area code
```

Every item is declared `Shape`, yet each runs a different `Area`. The runtime picks the method
body based on the object's **real** type — this is called *dynamic dispatch*.

## Why this matters

```csharp
static double TotalArea(IEnumerable<Shape> shapes) => shapes.Sum(s => s.Area());
```

`TotalArea` works for every shape that exists **and every shape invented in the future**. Add a
`Pentagon` class and this method needs no change at all.

That is the Open/Closed principle ([2.13](2.13.md)): open to extension, closed to modification.
Without polymorphism you would write a `switch` and edit it forever.

## `virtual` and `override`

`virtual` provides a default the child *may* replace:

```csharp
public class Notifier
{
    public virtual string Send(string message) => $"[log] {message}";
}

public class EmailNotifier : Notifier
{
    public override string Send(string message) => $"[email] {message}";
}
```

Both keywords are required. C# will not let you override by accident — a deliberate contrast
with Java, where every method is virtual by default.

## `base.Method()`

Extend the parent rather than replacing it:

```csharp
public class LoudEmailNotifier : EmailNotifier
{
    public override string Send(string message) => base.Send(message) + " !!!";
}
```

## `abstract`

`abstract` means there is **no** default — every concrete child must supply one:

```csharp
public abstract class Shape
{
    public abstract double Area();          // no body at all
    public abstract double Perimeter();

    public virtual string Summary() => $"{Name}: area {Area():F2}";   // a default
}
```

| | `virtual` | `abstract` |
|---|---|---|
| Has a body | yes | no |
| Child must override | no | **yes** |
| Class can be instantiated | yes | **no** |

You cannot write `new Shape()`. There is nothing to run.

## Overriding `ToString`

The most useful override of all — it gives every object a readable form, and string
interpolation picks it up automatically:

```csharp
public override string ToString() => Summary();

Console.WriteLine($"{shapes[1]}");     // uses your ToString
```

## `new` vs `override` — a classic trap

```csharp
public class Base    { public virtual string Speak() => "Base"; }

public class WithOverride : Base { public override string Speak() => "Derived"; }
public class WithNew      : Base { public new      string Speak() => "Derived"; }
```

```csharp
Base a = new WithOverride();   a.Speak();   // "Derived"  ✅
Base b = new WithNew();        b.Speak();   // "Base"     ⚠️
new WithNew().Speak();                      // "Derived"
```

`new` **hides** the method rather than replacing it, so which one runs depends on the
*declared* type of the variable, not the real object. This is almost always a bug. The compiler
warns you; listen to it and use `override`.

## The three kinds of polymorphism

| Kind | Mechanism | Decided |
|---|---|---|
| **Subtype** | `virtual` / `override` | at run time |
| **Ad hoc** | method overloading ([1.9](../module-1/1.9.md)) | at compile time |
| **Parametric** | generics ([3.4](../module-3/3.4.md)) | at compile time |

When people say "polymorphism" unqualified they almost always mean the first.

## Common mistakes

| Mistake | Result |
|---|---|
| Forgetting `virtual` on the parent | Cannot override — compile error |
| Using `new` instead of `override` | Wrong method runs, silently |
| `abstract` method with a body | Compile error |
| Instantiating an abstract class | Compile error |
| A `switch` on a type instead of a virtual call | Works, but must be edited for every new type |
