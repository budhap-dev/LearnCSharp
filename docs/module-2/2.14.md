## What a pattern is

A **named, proven solution to a problem that keeps recurring**. Not a library, not code to copy
and paste.

The real benefit is a **shared vocabulary**: "use a factory here" replaces a paragraph of
explanation.

## Strategy — swap the algorithm at run time

```csharp
public interface IDiscount { decimal Apply(decimal total); }

public class Basket
{
    // The Basket does not know or care which discount it was handed
    public string Checkout(IDiscount discount) => $"{discount.Apply(_total):C}";
}
```

```csharp
basket.Checkout(new NoDiscount());
basket.Checkout(new PercentageDiscount(10));
basket.Checkout(new StudentDiscount());
```

You have used this already: `List.Sort(comparison)` and LINQ's `Where(predicate)` are both
Strategy. **The most useful pattern there is.**

## Factory — centralise how objects are made

```csharp
public static class EnemyFactory
{
    public static Enemy Create(string kind) => kind switch
    {
        "goblin" => new Enemy("Goblin", 30, 5),
        "dragon" => new Enemy("Dragon", 500, 90),
        _ => throw new ArgumentException($"Unknown enemy: {kind}"),
    };
}
```

Game code says `Create("dragon")` and never writes `new Dragon()`. Change how a dragon is built,
or add a Lich, and only the factory changes.

## Observer — tell everyone who cares

```csharp
public class Newsletter
{
    private readonly List<ISubscriber> _subscribers = new();

    public void Publish(string story)
    {
        foreach (ISubscriber s in _subscribers) s.Receive(story);
    }
}
```

The publisher has no idea what any subscriber does with the story. C# has this **built into the
language**: `event` *is* the Observer pattern ([4.3](../module-4/4.3.md)).

## Singleton — exactly one instance, ever

```csharp
public sealed class GameSettings
{
    private static readonly Lazy<GameSettings> _instance = new(() => new GameSettings());

    private GameSettings() { }        // private constructor: nobody else can call new

    public static GameSettings Instance => _instance.Value;
}
```

> ⚠️ **Singleton is the most over-used pattern in existence.** It is global state in disguise:
> it makes testing hard, hides dependencies, and causes threading bugs. Almost always, what you
> actually want is to create **one** instance and inject it ([2.13](2.13.md), D).
>
> Learn to recognise it. Use it rarely.

## Repository — hide where the data lives

```csharp
public interface IBookRepository
{
    void Add(StoredBook book);
    StoredBook? GetById(int id);
    List<StoredBook> GetAll();
}
```

Swap `InMemoryBookRepository` for `SqlBookRepository` or `JsonBookRepository` and nothing else
changes. You used exactly this in project [7.4](../module-7/7.4.md) with `ITodoStore`.

## Adapter — make an incompatible thing fit

```csharp
// We speak ILogTarget. The third-party class does not. The adapter translates.
public class LegacyLoggerAdapter : ILogTarget
{
    private readonly LegacyLogger _legacy;

    public string Write(string message) => _legacy.WriteEntry(1, message);
}
```

Use it when you **cannot change** the other class — a NuGet package, an old system, someone
else's API.

## Decorator — add behaviour by wrapping

```csharp
ICoffee coffee = new SimpleCoffee();     // £2.00
coffee = new WithMilk(coffee);           // £2.40
coffee = new WithSyrup(coffee);          // £3.00
coffee = new WithExtraShot(coffee);      // £3.80
```

Each decorator wraps the previous one. Inheritance could never give you every combination — you
would need `MilkSyrupExtraShotCoffee` and dozens more classes.

`Stream` in .NET works exactly this way: `new GZipStream(new FileStream(...))`.

## The three families

| Family | Concerns | Examples |
|---|---|---|
| **Creational** | how objects are made | Factory, Builder, Singleton, Prototype |
| **Structural** | how objects are composed | Adapter, Decorator, Facade, Composite, Proxy |
| **Behavioural** | how objects interact | Strategy, Observer, Command, State, Iterator |

## Patterns you already use without knowing

| Pattern | Where |
|---|---|
| Iterator | `foreach` and `IEnumerable` ([3.5](../module-3/3.5.md)) |
| Observer | events ([4.3](../module-4/4.3.md)) |
| Strategy | passing a `Func` or `Comparison` ([4.1](../module-4/4.1.md)) |
| Decorator | `Stream` wrapping `Stream` ([4.9](../module-4/4.9.md)) |
| Composite | a tree of folders containing folders ([5.4](../module-5/5.4.md)) |

## The health warning

> Patterns are a vocabulary for problems you **have**, not a shopping list.

Forcing five patterns into a small program produces code that is harder to read, not easier.
Write the simple version first; reach for a pattern when the simple version starts to hurt.
