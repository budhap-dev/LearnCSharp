## The one distinction that explains everything

**Assigning a value type copies the value. Assigning a reference type copies the arrow.**

```csharp
PointStruct a = new(1, 2);
PointStruct b = a;          // a full, independent copy
b.X = 99;
// a.X is still 1

PointClass c = new(1, 2);
PointClass d = c;           // both names point at ONE object
d.X = 99;
// c.X is now 99
```

Get this wrong and you will spend hours on bugs that make no sense.

## Passing to a method follows the same rule

```csharp
static void Mutate(PointStruct p) => p.X = 99;   // caller unaffected
static void Mutate(PointClass  p) => p.X = 99;   // caller SEES this
```

## Which is which

| Value types | Reference types |
|---|---|
| `int`, `double`, `bool`, `char`, `decimal` | `string` |
| `DateTime`, `TimeSpan` | arrays, `List<T>`, `Dictionary<K,V>` |
| every `struct` | every `class` |
| every `enum` | records, delegates |

> `string` is a **reference** type, but because it is immutable it *behaves* like a value type.
> That is why `==` on strings compares characters and never surprises you.

## Where they live

| Thing | Lives |
|---|---|
| A value-type local variable | the **stack** — freed the instant the method returns |
| An object | the **heap** — freed later by the garbage collector |
| A reference variable | arrow on the stack, object on the heap |
| A value type *inside* an object | the heap, with its owner |

More on this in [4.8](../module-4/4.8.md).

## Equality differs too

```csharp
structA.Equals(new PointStruct(1, 2))   // true  - compares field by field
classC.Equals(new PointClass(1, 2))     // false - different objects
```

Structs compare contents by default. Classes compare **identity** — is it literally the same
object? — unless you override `Equals` ([2.10](2.10.md)).

## Writing a struct

```csharp
public readonly struct Money
{
    public Money(decimal amount, string currency)
    {
        Amount = amount;
        Currency = currency;
    }

    public decimal Amount { get; }
    public string Currency { get; }

    // Returns a NEW Money rather than changing this one
    public Money Add(decimal extra) => new(Amount + extra, Currency);
}
```

`readonly struct` is the safest kind: nothing can change after construction, which removes
every mutable-struct surprise at once.

**Use a struct when** it is small (roughly ≤ 16 bytes), logically a single value, immutable, and
created in large numbers. Otherwise use a class.

## Nullable value types

A value type cannot normally be null. `int?` — shorthand for `Nullable<int>` — allows it:

```csharp
int? maybe = null;
maybe.HasValue              // false
maybe ?? -1                 // -1
maybe.GetValueOrDefault(99) // 99

maybe = 42;
maybe.Value                 // 42
```

Note the difference from `string?`: `int?` is a genuinely different type at run time, whereas
`string?` is only a compiler annotation ([4.5](../module-4/4.5.md)).

## Enums

A fixed set of named values:

```csharp
public enum Difficulty { Easy, Medium, Hard }     // 0, 1, 2

Difficulty level = Difficulty.Hard;
(int)level                              // 2
Enum.Parse<Difficulty>("Medium")        // Difficulty.Medium
Enum.GetNames<Difficulty>()             // ["Easy", "Medium", "Hard"]
```

Enums are ideal in a `switch` because the compiler can see every case:

```csharp
int lives = difficulty switch
{
    Difficulty.Easy => 5,
    Difficulty.Medium => 3,
    Difficulty.Hard => 1,
    _ => 3,
};
```

> Use an enum instead of "magic strings" or bare numbers. `Difficulty.Hard` cannot be
> misspelled; `"hrad"` can.

## Flags enums

For values meant to be **combined**, give them powers of two:

```csharp
[Flags]
public enum Permissions
{
    None = 0, Read = 1, Write = 2, Delete = 4,
    All = Read | Write | Delete,
}

Permissions granted = Permissions.Read | Permissions.Write;
granted.HasFlag(Permissions.Read)     // true
granted.HasFlag(Permissions.Delete)   // false
```

Each value occupies its own bit, so they pack into a single number — the bitwise operators from
[1.4](../module-1/1.4.md) doing real work.

## Common mistakes

| Mistake | Result |
|---|---|
| Expecting `b = a` to copy an object | Both names point at one object |
| A mutable struct | Changes vanish, because you edited a copy |
| A large struct | Copying it everywhere is slower than a reference |
| Flags enum without powers of two | Values overlap and `HasFlag` lies |
| Comparing classes with `==` expecting content equality | Override `Equals` first ([2.10](2.10.md)) |
