## Rule one: measure, never guess

Programmers' intuition about what is slow is famously wrong. The discipline:

1. Write it clearly first.
2. **Measure** — find the actual hot spot.
3. Fix the top item.
4. Measure again.

Measuring honestly means: **Release** builds, warm up first (the JIT compiles a method on its
first call — [1.1](../module-1/1.1.md)), repeat the work, and distrust differences under 2×
from a simple `Stopwatch`. For real work, **BenchmarkDotNet** does warm-up, statistics and
memory columns properly; `Stopwatch` is the classroom tool.

## Allocations are the hidden cost

Allocating is fast — bump a pointer. The price comes later: **every allocation is future
garbage-collector work** ([4.8](../module-4/4.8.md)). One allocation is free; millions per
second are pauses.

The lesson demonstrates the classic invisible allocator — **boxing**:

```csharp
object o = i;          // BOX: the int copied to the heap
sum += (int)o;         // UNBOX: copied back
```

Two million adds through `object` run several times slower than plain `int` adds and trigger
a stream of gen-0 collections. This is [3.4](../module-3/3.4.md)'s closing argument replayed
with numbers: generics exist so `List<int>` never boxes.

## The three cheap wins

**StringBuilder** ([1.8](../module-1/1.8.md), now with mechanism): `s += "x"` in a loop is
quadratic copying. Measured: ~hundreds of ms vs ~1 ms for 20,000 appends.

**Capacity hints**: a default `List<int>` doubles ~21 times on the way to 2 million items,
copying everything each time. `new List<int>(2_000_000)` skips every copy:

```csharp
new List<int>(expected);  new Dictionary<K,V>(expected);  new StringBuilder(expected);
```

The cheapest optimisation in the language — one constructor argument.

**Struct arrays** ([2.8](../module-2/2.8.md) at scale): a million `PointClass` objects =
1,000,001 heap allocations chased through references. A million `PointStruct` in an array =
**one** allocation, values contiguous, cache-friendly — measured ~5× faster to build, and
faster again to iterate.

## Span&lt;T&gt;: slicing without copying

```csharp
Span<int> window = data.AsSpan(10, 10);   // a VIEW, not a copy
window[0] = 999;                          // writes through to the array
```

`data[10..20]` on an array copies ten items; a span is just a window over existing memory —
array, string middle, or (`stackalloc`) a small stack buffer with no heap at all.
High-performance parsing is built on this type. Know it exists; reach for it when profiling
points at slicing.

## Premature optimisation — the other failure mode

> "Premature optimisation is the root of all evil" — Knuth

It means: clarity first, optimise the *measured* hot spot. It does **not** mean ignoring an
obvious `O(n²)` or a `List.Contains` inside a loop ([5.1](../module-5/5.1.md)) — choosing the
right algorithm and collection is design, not premature anything.

## The short list that usually matters, in order

1. **Algorithm** — O(n²) → O(n log n) beats every micro-tune (module 5)
2. **Right collection** — `Dictionary`/`HashSet` for lookups ([3.2](../module-3/3.2.md))
3. **Fewer allocations** — StringBuilder, capacity hints, structs, Span
4. **Batch the I/O** — one big read beats a thousand small ones ([4.9](../module-4/4.9.md))
5. **Parallel last** — big independent chunks only, measured ([6.1](6.1.md))

## Common mistakes

| Mistake | Why it misleads |
|---|---|
| Timing Debug builds | The optimiser is off — numbers are fiction |
| Timing the first call | You measured the JIT, not the method |
| One run, tiny input | Noise dominates; grow and repeat |
| Optimising unmeasured code | You polish the cold path |
| Boxing in a hot loop | Invisible in the source, visible in GC counts |

## Exercises

1. Time `string +=` vs `StringBuilder` at 1k, 10k, 50k iterations and plot the shape — is it
   linear or quadratic?
2. Measure `List<int>` growth with and without a capacity hint at 10 million items.
3. Build the million-point comparison yourself, then also time *summing* X across both
   arrays — the iteration gap is the cache talking.
4. Find the deliberate O(n²) in this course (hint: [1.8](../module-1/1.8.md)) and explain
   where its hidden inner loop is.
