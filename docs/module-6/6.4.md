## Beyond round-tripping

[4.9](../module-4/4.9.md) serialised simple objects. Real data is messier: JSON written by
other systems, class hierarchies, and — the one everyone learns the hard way — **old saved
files that must keep loading after your model changes**.

## Naming policies

JSON convention is `camelCase`; C# convention is `PascalCase`. Bridge them once, in options —
never by renaming your properties:

```csharp
JsonSerializerOptions options = new()
{
    PropertyNamingPolicy = JsonNamingPolicy.CamelCase,
    PropertyNameCaseInsensitive = true,        // forgive either on the way in
};
```

## Per-property attributes

```csharp
[JsonPropertyName("display_name")]   // rename one property
public string Name { get; set; }

[JsonIgnore]                          // NEVER reaches the file
public string Secret { get; set; }

[JsonIgnore(Condition = JsonIgnoreCondition.WhenWritingNull)]
public string? Nickname { get; set; } // omitted when null - smaller files, cleaner diffs
```

`[JsonIgnore]` on secrets is a security habit ([6.3](6.3.md)), not a formatting one.

## Custom converters

When the default shape is wrong for a type, a converter owns the format — the whole thing is
~15 lines:

```csharp
public class MoneyConverter : JsonConverter<Money>
{
    public override Money Read(ref Utf8JsonReader reader, ...) 
    {
        string[] parts = reader.GetString()!.Split(' ');
        return new Money(decimal.Parse(parts[0]), parts[1]);
    }

    public override void Write(Utf8JsonWriter writer, Money value, ...)
        => writer.WriteStringValue($"{value.Amount} {value.Currency}");
}
```

Now `Money` serialises as `"49.99 GBP"` instead of a nested object. Dates, units and legacy
formats all get the same treatment.

## Polymorphism: saving a list of different shapes

Serialise a `List<Shape>` naively and the subtypes are lost. The base class declares its
children:

```csharp
[JsonDerivedType(typeof(Circle), "circle")]
[JsonDerivedType(typeof(Rect), "rect")]
public abstract record Shape;
```

```json
[{"$type":"circle","Radius":3},{"$type":"rect","Width":4,"Height":5}]
```

The `$type` discriminator rebuilds the right subclass on the way back — verified in the
lesson with `loaded[0] is Circle`. This is the [4.6](../module-4/4.6.md) shape hierarchy made
saveable.

## Schema versioning — the rules that save you

Your app ships v1. Users save files. You ship v2 with a changed model. **Old files must keep
loading.**

| Rule | Why |
|---|---|
| **Add** new properties, with defaults | Absent in old files → default supplied. Free back-compat. |
| **Never rename** | Old files carry the old name; the value silently vanishes. |
| **Never repurpose** | Changing a field's *meaning* corrupts data with no error at all. |
| **Version explicitly** | A `SchemaVersion` property enables real migrations. |

The lesson demonstrates rule 1 live (a v1 file loading into a v2 model, new `Health` property
defaulting to 100) and sketches the migration ladder for bigger changes: read the version,
then `Migrate1To2`, `2To3`… — each step small and testable.

## JsonDocument: reading without a class

```csharp
using JsonDocument doc = JsonDocument.Parse(unknown);
double first = doc.RootElement.GetProperty("readings")[0].GetDouble();
```

For JSON whose shape you do not control, or only need one field of — no class declaration
needed.

## Other formats, honestly

| Format | Verdict |
|---|---|
| JSON | The default: readable, universal |
| XML | Alive in old systems and config; `XmlSerializer` exists |
| CSV | Tables for spreadsheets — you hand-rolled one in [4.11](../module-4/4.11.md) |
| Binary (protobuf…) | Smaller and faster when both ends are yours |
| `BinaryFormatter` | **Removed from modern .NET** — deserialising hostile bytes could execute code. Meeting it in old code is a security bug ([6.3](6.3.md)). |

## Common mistakes

| Mistake | Result |
|---|---|
| Renaming a serialised property | Old data silently lost |
| No version field from day one | Migrations become guesswork |
| Rebuilding `JsonSerializerOptions` per call | Slow — cache and share it |
| Trusting deserialised data | Nulls where "impossible" ([4.5](../module-4/4.5.md)) — validate at the boundary |
| Secrets without `[JsonIgnore]` | Passwords in save files |

## Exercises

1. Serialise a class with all three attributes from this page and inspect the JSON.
2. Write a converter storing `DateOnly` as `"17/08/2026"` and round-trip it.
3. Make a small `Animal`/`Dog`/`Cat` hierarchy polymorphic and verify types survive.
4. Ship "v1", save a file, add two properties for "v2", and prove the old file still loads.
   Then rename a property and watch what happens.
