## The problem generics solve

You have been writing `List<int>` and `Dictionary<string, int>` all module. The angle brackets
are *generics* — and they exist because the alternative was genuinely bad.

Before generics, a general-purpose container had to store `object`:

```csharp
public class ObjectBox
{
    public object? Item { get; set; }
}

box.Item = "hello";
string s = (string)box.Item!;    // cast needed on every read
int n = (int)box.Item!;          // COMPILES fine - explodes at RUN time
```

Two costs: casts everywhere, and mistakes that surface as `InvalidCastException` in front of a
user instead of as compile errors in front of you.

## The generic version

```csharp
public class Box<T>
{
    public Box(T item) => Item = item;
    public T Item { get; set; }
}
```

`T` is a **type parameter** — a placeholder filled in by whoever uses the class:

```csharp
Box<string> words = new("hello");
words.Item.Length          // no cast - the compiler KNOWS it is a string
words.Item = 42;           // does not compile
```

One class, every type, full compile-time safety. `List<T>`, `Dictionary<TKey, TValue>`,
`Stack<T>` — the whole of Module 3 is this one idea.

## Generic methods

Methods can have their own type parameters, independent of any class:

```csharp
static T First<T>(T[] items) => items[0];

First(new[] { 3, 1, 2 })          // 3       - T inferred as int
First(new[] { "c", "a" })         // "c"     - T inferred as string
First<string>(names)              // stated explicitly - rarely needed
```

The compiler usually **infers** `T` from the arguments, which is why you have called dozens of
generic methods without noticing.

## Constraints: demanding capabilities of T

Inside a generic method, `T` could be *anything* — so you can only do things every type
supports. This will not compile:

```csharp
static T Largest<T>(T[] items)
{
    if (item.CompareTo(best) > 0)     // error: T might not have CompareTo
}
```

A **constraint** narrows `T` in exchange for capability:

```csharp
static T Largest<T>(T[] items) where T : IComparable<T>
{
    T best = items[0];
    foreach (T item in items)
        if (item.CompareTo(best) > 0) best = item;
    return best;
}

Largest([3, 9, 2])              // 9
Largest(["pear", "apple"])      // "pear"
Largest(new object[] { ... })   // does not compile - object is not IComparable
```

| Constraint | Demands |
|---|---|
| `where T : IComparable<T>` | implements that interface |
| `where T : Animal` | is `Animal` or derives from it |
| `where T : class` | reference type |
| `where T : struct` | value type |
| `where T : new()` | has a parameterless constructor, so you may write `new T()` |
| `where T : notnull` | not nullable |

## Building something real: a stack from scratch

```csharp
public class SimpleStack<T>
{
    private T[] _items = new T[4];

    public int Count { get; private set; }

    public void Push(T item)
    {
        if (Count == _items.Length) Array.Resize(ref _items, _items.Length * 2);
        _items[Count] = item;
        Count++;
    }

    public T Pop()
    {
        if (Count == 0) throw new InvalidOperationException("The stack is empty.");
        Count--;
        return _items[Count];
    }
}
```

Twenty lines, works for every type that will ever exist, and no casts anywhere. This is
`Stack<T>` with the polish removed — [5.6](../module-5/5.6.md) finishes the job.

## Multiple type parameters

```csharp
public record Pair<TFirst, TSecond>(TFirst First, TSecond Second)
{
    public Pair<TSecond, TFirst> Swap() => new(Second, First);
}
```

Convention: a single parameter is `T`; several get descriptive names — `TKey`, `TValue`,
`TResult`.

## Generics cost nothing at run time

For value types, the runtime generates a **specialised** version per type: `List<int>` stores
real ints in a real int array — no boxing ([4.8](../module-4/4.8.md)), no casts, no overhead.
Generics are simultaneously safer *and* faster than the `object` approach. There is no
trade-off to weigh; always prefer them.

## Common mistakes

| Mistake | Fix |
|---|---|
| Calling members `T` is not guaranteed to have | Add a constraint |
| `new T()` without `where T : new()` | Add the constraint |
| Casting through `object` inside a generic | Defeats the whole point — constrain instead |
| A generic class that only ever uses one type | Just use the type |
