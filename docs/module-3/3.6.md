## The idea

LINQ (**L**anguage **In**tegrated **Q**uery) replaces the loop-and-accumulate pattern you have
written fifty times with a single declarative line:

```csharp
// before
List<string> passed = new();
foreach (Pupil p in pupils)
    if (p.Mark >= 60) passed.Add(p.Name);

// after
var passed = pupils.Where(p => p.Mark >= 60).Select(p => p.Name);
```

You say **what** you want; the loop is implied. Every operator takes an `IEnumerable<T>` and
returns one, so they chain — and they are lazy ([3.5](3.5.md)) until something consumes them.

The examples below use a `record Pupil(string Name, int Year, string Subject, int Mark)`.

## The big three

**Where** — keep the items that match:

```csharp
pupils.Where(p => p.Mark > 80)
pupils.Where(p => p.Year == 10 && p.Mark > 70)
```

**Select** — transform each item into something else:

```csharp
pupils.Select(p => p.Name)                      // pupils -> names
pupils.Select(p => $"{p.Name}: {p.Mark}")       // pupils -> strings
pupils.Select(p => new { p.Name, Passed = p.Mark >= 60 })   // -> anonymous type
```

**OrderBy** — sort by a key:

```csharp
pupils.OrderBy(p => p.Mark)                     // ascending
pupils.OrderByDescending(p => p.Mark)
pupils.OrderBy(p => p.Subject).ThenByDescending(p => p.Mark)   // tiebreaks
```

Unlike `List.Sort`, these return a **new** sequence and leave the source untouched.

## Chaining is the whole point

```csharp
pupils.Where(p => p.Year == 10)
      .Where(p => p.Mark >= 60)
      .OrderByDescending(p => p.Mark)
      .Select(p => $"{p.Name} ({p.Mark})")
```

Read it top to bottom like a sentence: year 10, who passed, best first, as name-and-mark.

> Order matters for efficiency: filter with `Where` **before** you transform with `Select`, so
> you transform fewer items.

## Getting single items

| Method | No match | Two matches |
|---|---|---|
| `First(p => ...)` | **throws** | first wins |
| `FirstOrDefault(p => ...)` | `null`/default | first wins |
| `Single(p => ...)` | **throws** | **throws** |
| `SingleOrDefault(p => ...)` | `null`/default | **throws** |
| `Last(...)` / `LastOrDefault(...)` | as First, from the end | |

Choose deliberately: `FirstOrDefault` when absence is normal; `Single` when two matches would
mean corrupt data and you *want* the exception.

## Aggregation

```csharp
pupils.Count()                        // 7
pupils.Count(p => p.Mark >= 70)       // count matching
pupils.Sum(p => p.Mark)
pupils.Average(p => p.Mark)
pupils.Min(p => p.Mark)
pupils.Max(p => p.Mark)
pupils.MaxBy(p => p.Mark)             // the PUPIL with the top mark, not the mark
pupils.MinBy(p => p.Mark)
```

`Max` gives you the highest *value*; `MaxBy` gives you the *item* that has it. Reaching for
`Max` then searching for its owner is the long way round.

## Any and All

```csharp
pupils.Any(p => p.Mark > 90)     // does at least one match?
pupils.All(p => p.Mark >= 50)    // do they all match?
pupils.Any()                     // is there anything at all?
```

> Prefer `Any()` over `Count() > 0`: `Any` stops at the first item; `Count` walks the lot.

## Paging: Skip and Take

```csharp
pupils.Take(3)               // first three
pupils.Skip(3).Take(3)       // page 2, page size 3
pupils.TakeLast(2)
```

## Distinct and set operations

```csharp
pupils.Select(p => p.Subject).Distinct()      // each subject once
pupils.DistinctBy(p => p.Year)                // one pupil per year

a.Union(b)        a.Intersect(b)      a.Except(b)     // on any two sequences
```

## Query syntax — the other spelling

```csharp
var top =
    from pupil in pupils
    where pupil.Year == 10
    orderby pupil.Mark descending
    select $"{pupil.Name} ({pupil.Mark})";
```

Identical meaning, SQL-ish look. Method syntax is what you will see in most real codebases;
read both, write whichever is clearer for the query at hand.

## Materialising

```csharp
.ToList()          .ToArray()
.ToDictionary(p => p.Name, p => p.Mark)
.ToHashSet()
```

These *run* the query and fix the result — the lazy/eager boundary from [3.5](3.5.md).

## Common mistakes

| Mistake | Fix |
|---|---|
| `First()` on a possibly-empty result | `FirstOrDefault`, then null-check |
| `Where(...).First()` | `First(...)` takes the predicate directly |
| `Count() > 0` | `Any()` |
| `Select` before `Where` | Filter first |
| Sorting with `Sort()` when you meant a query | `Sort` mutates; `OrderBy` does not |
