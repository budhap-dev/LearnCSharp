## The idea

Part 1 worked item by item. This lesson is about **reshaping** data: turning a flat list of
records into grouped summaries, joined tables and reports — the everyday work of real programs.

Running example: `record Sale(string Customer, string Category, decimal Amount, DateOnly Date)`.

## GroupBy — buckets keyed by something

```csharp
foreach (IGrouping<string, Sale> group in sales.GroupBy(s => s.Category))
    Console.WriteLine($"{group.Key}: {group.Count()} sales, total {group.Sum(s => s.Amount)}");
```

An `IGrouping<TKey, T>` is a small sequence with a `.Key` attached. Each group is itself
enumerable, so every part-1 operator works *inside* it.

### Group, then shape the summary

The workhorse pattern — group, then `Select` each group into a tidy row:

```csharp
var byCustomer = sales
    .GroupBy(s => s.Customer)
    .Select(g => new
    {
        Customer = g.Key,
        Orders = g.Count(),
        Total = g.Sum(s => s.Amount),
        Best = g.Max(s => s.Amount),
    })
    .OrderByDescending(x => x.Total);
```

That is a complete "sales by customer" report in one statement. Commit this shape to memory —
you will write it hundreds of times.

### The key can be computed

```csharp
sales.GroupBy(s => s.Amount >= 20)                    // big vs small
sales.GroupBy(s => s.Date.Month switch { 1 or 2 or 3 => "Q1", _ => "later" })
```

Any expression works: a property, a bool, a calculation, a range label.

## Join — match two sequences on a key

```csharp
var joined = customers.Join(
    sales,
    customer => customer.Name,       // key from the left sequence
    sale => sale.Customer,           // key from the right
    (customer, sale) => new { customer.City, sale.Category, sale.Amount });
```

Like a database inner join: only pairs where the keys match survive. A customer with no sales
disappears from the result entirely.

## GroupJoin — keep everyone

```csharp
var withTotals = customers.GroupJoin(
    sales,
    customer => customer.Name,
    sale => sale.Customer,
    (customer, theirSales) => new { customer.Name, Total = theirSales.Sum(s => s.Amount) });
```

Each customer appears once, paired with *all* their sales — an empty group if they have none,
so the no-sales customer shows up with a total of 0 instead of vanishing. Choose `Join` vs
`GroupJoin` by asking: *should unmatched items disappear or appear empty?*

## SelectMany — flatten nested collections

```csharp
record Basket(string Owner, List<string> Items);

baskets.Select(b => b.Items)       // sequence OF LISTS - usually not what you want
baskets.SelectMany(b => b.Items)   // one flat sequence of items

// keep the owner attached while flattening:
baskets.SelectMany(b => b.Items, (basket, item) => $"{basket.Owner}:{item}")
```

Whenever you catch yourself with a `List<List<T>>` and a nested foreach, `SelectMany` is the
operator you were looking for.

## Aggregate — fold a sequence into one value

```csharp
numbers.Aggregate((total, n) => total + n)        // sum, by hand
numbers.Aggregate((total, n) => total * n)        // product
numbers.Aggregate(100, (total, n) => total + n)   // with a seed
words.Aggregate((a, b) => a + " " + b)            // join words
```

`Aggregate` is the general form that `Sum`, `Min`, `Max` are shortcuts for. Reach for it only
when no named operator fits — the named ones say what they mean.

## The utility belt

```csharp
names.Zip(scores, (n, s) => $"{n}={s}")     // pair items positionally
Enumerable.Range(5, 4)                       // 5, 6, 7, 8  (start, COUNT)
Enumerable.Repeat("ab", 3)                   // ab, ab, ab
numbers.Chunk(4)                             // arrays of at most 4
sales.ToLookup(s => s.Customer)              // like GroupBy, but pre-built and reusable;
                                             // lookup["Nobody"] is empty, never an error
```

## A realistic report, end to end

```csharp
var report = sales
    .Where(s => s.Amount > 10)                     // filter first
    .GroupBy(s => s.Category)                      // bucket
    .Select(g => new                               // summarise each bucket
    {
        Category = g.Key,
        Revenue = g.Sum(s => s.Amount),
        Count = g.Count(),
    })
    .OrderByDescending(x => x.Revenue)             // rank
    .ToList();                                     // run it, once
```

Filter → group → summarise → order → materialise. Most reporting queries you ever write will
be this pipeline with different names in it.

## Performance notes

| Habit | Why |
|---|---|
| `Where` before `GroupBy`/`Select` | fewer items to bucket and shape |
| `ToList()` once at the end, not mid-chain | avoid materialising intermediates |
| Reusing a grouping? `ToLookup` | `GroupBy` re-runs per enumeration ([3.5](3.5.md)) |
| Joining by key repeatedly? `ToDictionary` first | O(1) lookups instead of scans |

## Common mistakes

| Mistake | Result |
|---|---|
| Forgetting `.Key` on a group | Compile error hunting for the key property |
| `Join` when unmatched rows matter | They silently vanish — use `GroupJoin` |
| `Select` where flattening was needed | A sequence of lists — use `SelectMany` |
| Growing an unreadable one-liner | Split it: name the intermediate queries |
