## The idea

`List` and `Dictionary` let you touch any item at any time. Stacks and queues deliberately
**restrict** access — and the restriction is the feature. When only one item is reachable,
whole categories of bugs become impossible, and many algorithms become almost trivial.

## Stack: last in, first out (LIFO)

Like a stack of plates: you add to the top and take from the top.

```csharp
Stack<string> plates = new();
plates.Push("bottom");
plates.Push("middle");
plates.Push("top");

plates.Peek()     // "top"    - look without taking
plates.Pop()      // "top"    - take it off
plates.Pop()      // "middle"
```

`Pop` on an empty stack throws `InvalidOperationException`; `TryPop(out var item)` returns
`false` instead. Same for `Peek`/`TryPeek`.

**Where stacks appear:** the call stack itself ([1.11](../module-1/1.11.md)), undo history, the
browser back button, matching brackets, depth-first search ([5.8](../module-5/5.8.md)),
expression evaluation.

### Reversing is free

Push everything on, pop everything off — it comes back reversed:

```csharp
Stack<char> letters = new();
foreach (char c in "stressed") letters.Push(c);
string.Concat(letters)     // "desserts"
```

### The classic: matching brackets

Every opening bracket must be closed **in the right order** — which is exactly LIFO:

```csharp
static bool IsBalanced(string expression)
{
    Stack<char> open = new();

    foreach (char c in expression)
    {
        if (c is '(' or '[' or '{')
        {
            open.Push(c);
        }
        else if (c is ')' or ']' or '}')
        {
            if (open.Count == 0) return false;               // closing with nothing open

            char last = open.Pop();
            bool matches = (last, c) is ('(', ')') or ('[', ']') or ('{', '}');
            if (!matches) return false;                      // wrong kind
        }
    }

    return open.Count == 0;                                  // nothing left dangling
}
```

```csharp
IsBalanced("(a+b)*[c-d]")   // true
IsBalanced("{[(])}")        // false - ] arrived while ( was innermost
```

This is how every compiler — including C#'s — checks your braces.

## Queue: first in, first out (FIFO)

Like a checkout queue: join at the back, served from the front.

```csharp
Queue<string> checkout = new();
checkout.Enqueue("Ada");
checkout.Enqueue("Alan");
checkout.Enqueue("Grace");

checkout.Peek()      // "Ada"  - who is next
checkout.Dequeue()   // "Ada"  - serve them
checkout.Dequeue()   // "Alan"
```

**Where queues appear:** print spoolers, keyboard buffers, message queues, task scheduling,
breadth-first search ([5.8](../module-5/5.8.md)) — anything first-come-first-served.

## PriorityQueue: most urgent out first

```csharp
PriorityQueue<string, int> hospital = new();
hospital.Enqueue("sprained ankle", 5);
hospital.Enqueue("chest pain", 1);
hospital.Enqueue("broken arm", 3);

hospital.Dequeue()    // "chest pain"  - LOWEST priority number first
hospital.Dequeue()    // "broken arm"
```

Note the direction: **lowest number = served first**. Dijkstra's algorithm
([5.8](../module-5/5.8.md)) is built on exactly this collection.

## LinkedList: cheap inserts, no indexing

A chain of nodes, each pointing at the next and previous:

```csharp
LinkedList<int> chain = new([10, 20, 30]);

LinkedListNode<int> twenty = chain.Find(20)!;
chain.AddAfter(twenty, 25);        // O(1) - just re-point two arrows
chain.AddBefore(twenty, 15);
chain.AddFirst(5);

// chain[2]   <- does not exist. No index, no O(1) access.
```

Honest advice: you will *use* `LinkedList<T>` rarely — `List<T>` beats it in practice on modern
hardware even at the things linked lists are theoretically good at. You *study* it because
trees and graphs are built from the same node-and-pointer idea, and [5.5](../module-5/5.5.md)
builds one from scratch so you can see inside.

## Choosing a collection — the full table

| You need | Use | Key operations |
|---|---|---|
| An ordered, growable sequence | `List<T>` | index, `Add` |
| Lookup by key | `Dictionary<K,V>` | `[key]`, `TryGetValue` |
| Uniqueness / membership | `HashSet<T>` | `Add`, `Contains` |
| Last in, first out | `Stack<T>` | `Push`, `Pop` |
| First in, first out | `Queue<T>` | `Enqueue`, `Dequeue` |
| Most urgent first | `PriorityQueue<T,P>` | `Enqueue`, `Dequeue` |
| Frequent inserts mid-sequence | `LinkedList<T>` | `AddAfter`, `Remove` |

## Common mistakes

| Mistake | Fix |
|---|---|
| `Pop`/`Dequeue` on empty | Check `Count`, or use `TryPop`/`TryDequeue` |
| Using a `List` as a queue via `RemoveAt(0)` | O(n) per removal — use `Queue<T>` |
| Expecting `stack[0]` | Stacks and queues have no indexer, by design |
| Priority queue: biggest number first | It is smallest-first — negate if needed |
