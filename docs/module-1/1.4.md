## Arithmetic

| Operator | Meaning | `17` and `5` |
|---|---|---|
| `+` `-` `*` | as expected | `22`, `12`, `85` |
| `/` | division | `3` ⚠️ |
| `%` | remainder (modulus) | `2` |

### The single most common beginner bug in C#

```csharp
int x = 17, y = 5;
x / y      // 3, NOT 3.4
```

**When both sides are whole numbers, C# does integer division and throws away the fraction.**
To get a real answer, make at least one side a decimal type:

```csharp
(double)x / y    // 3.4
x / (double)y    // 3.4
17.0 / 5         // 3.4
```

This bug is invisible — no error, no warning, just a wrong answer. Watch for it in any average
calculation.

### Why `%` matters

```csharp
n % 2 == 0                  // is it even?
i % 5 == 0                  // every 5th iteration
index = (index + 1) % n     // wrap around a circle of size n
```

Splitting a duration is the classic use:

```csharp
int totalSeconds = 3725;
int hours   = totalSeconds / 3600;        // 1
int minutes = totalSeconds % 3600 / 60;   // 2
int seconds = totalSeconds % 60;          // 5
```

### Division by zero behaves differently

```csharp
17 / 0        // throws DivideByZeroException      (integers)
17.0 / 0      // Infinity                          (doubles)
-17.0 / 0     // -Infinity
0.0 / 0.0     // NaN  - "not a number"
```

Check with `double.IsNaN(x)` and `double.IsInfinity(x)`. Note `NaN != NaN`, which is deliberate.

## Increment and compound assignment

```csharp
n++    // returns the OLD value, then adds 1
++n    // adds 1, then returns the NEW value

n += 5;   n -= 3;   n *= 2;   n /= 4;   n %= 4;
```

`i++` and `++i` differ only when you *use* the result. On a line of their own they are
identical. Prefer keeping them on their own line — `array[i++] = ++j` is a bug waiting to happen.

## Comparison

`==` `!=` `<` `>` `<=` `>=` — all produce a `bool`.

> `=` assigns, `==` compares. In C# you **cannot** accidentally write `if (x = 5)`, because `if`
> demands a `bool` and an assignment gives an `int`. In C that compiles and causes chaos.

## Logical operators

| Operator | Meaning |
|---|---|
| `&&` | AND — short-circuits |
| `\|\|` | OR — short-circuits |
| `!` | NOT |
| `^` | XOR |

**Short-circuiting** means: if the left side already decides the answer, the right side is never
evaluated. You *rely* on this for safety:

```csharp
if (words != null && words.Length > 0) { }   // safe: Length never touched when null
if (words != null &  words.Length > 0) { }   // single & evaluates BOTH -> crash
```

## Ternary `?:`

```csharp
string result = mark >= 50 ? "Pass" : "Fail";
```

Read it as: *condition* `?` *value if true* `:` *value if false*. Perfect for one simple choice.
If you chain three or more, use a `switch` expression ([1.5](1.5.md)) instead.

## The null operators

```csharp
nothing ?? "fallback"     // use the fallback when null
nothing?.Length           // null instead of crashing
username ??= "guest";     // assign only if currently null
```

Full treatment in [4.5](../module-4/4.5.md).

## Bitwise operators — the GCSE binary topic in code

```csharp
int p = 0b1100;    // 12
int q = 0b1010;    // 10

p & q     // 1000  AND
p | q     // 1110  OR
p ^ q     // 0110  XOR
~p        //       NOT (flips every bit)
p << 1    // 11000 left shift  - DOUBLES the number
p >> 1    // 0110  right shift - HALVES it
```

A left shift by 1 doubles; a right shift halves. That is exactly the binary-shift question from
the AQA specification.

## Precedence

From tightest to loosest:

1. `()` brackets
2. `!` `-` (unary)
3. `*` `/` `%`
4. `+` `-`
5. `<<` `>>`
6. `<` `>` `<=` `>=`
7. `==` `!=`
8. `&` → `^` → `|`
9. `&&` → `||`
10. `?:`
11. `=` `+=` …

```csharp
2 + 3 * 4      // 14
(2 + 3) * 4    // 20
```

> When in doubt, **add brackets**. Brackets are free; a misread expression costs an hour.

## Common mistakes

| Mistake | Fix |
|---|---|
| `total / count` giving a whole number | Cast: `(double)total / count` |
| `average = sum / 2` where both are ints | Same fix |
| `if (a = b)` | Use `==` (C# catches this, be glad) |
| `x & y` on bools when you meant `&&` | Use `&&` so short-circuiting protects you |
| `Next(1, 6)` for a dice | The upper bound is exclusive — use `Next(1, 7)` |

## Exercises

1. Write an expression that is `true` for a leap year: divisible by 4, but not by 100, unless
   also divisible by 400.
2. Given 254 minutes, print `"4h 14m"` using only `/` and `%`.
3. Given a number of pence, print pounds and pence (`1234` → `"£12.34"`).
4. Use `<<` and `>>` to double and halve a number, and print both in binary with
   `Convert.ToString(n, 2)`.
