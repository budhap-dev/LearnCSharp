## The idea

At GCSE you wrote `score ← 0`. In C# you must also say **what kind of data** the box holds:

```csharp
int score = 0;              // declare and assign at once
string playerName;          // declare now...
playerName = "Ada";         // ...assign later
```

The pattern is `type name = value;`.

C# is **statically typed**: the compiler now guarantees `score` can only ever hold a whole
number. Write `score = "twelve";` and the program will not even build. That is a *feature* —
mistakes are caught before a user ever sees them.

## The whole-number types

They differ only in how many bytes they use, which fixes how big a number they can hold.
Remember the GCSE binary topic: *n* bits gives 2ⁿ different values.

| Type | Bytes | Range |
|---|---|---|
| `sbyte` | 1 | −128 … 127 |
| `byte` | 1 | 0 … 255 |
| `short` | 2 | −32,768 … 32,767 |
| `ushort` | 2 | 0 … 65,535 |
| `int` | 4 | ±2.1 billion |
| `long` | 8 | ±9.2 quintillion |

> **Use `int` unless you have a reason not to.** It is the fastest on modern CPUs and big enough
> for almost everything. Reach for `long` when counting things like milliseconds since 1970.

## Overflow

What happens when you add 1 to the biggest `int`? By default C# **wraps around** silently, like
an odometer rolling over:

```csharp
int big = int.MaxValue;     // 2147483647
int wrapped = big + 1;      // -2147483648
```

Wrap the code in `checked` to turn that into an exception instead:

```csharp
checked
{
    int boom = int.MaxValue + 1;   // throws OverflowException
}
```

## The decimal types

| Type | Size | Precision | Use for |
|---|---|---|---|
| `float` | 4 bytes | ~7 digits | graphics, games — write `1.5f` |
| `double` | 8 bytes | ~15 digits | general maths — the default |
| `decimal` | 16 bytes | 28 digits, **exact base 10** | money — write `19.99m` |

`float` and `double` store numbers in binary floating point (the IEEE 754 standard). They are
fast but **approximate**:

```csharp
0.1 + 0.2 == 0.3       // false!   0.1 + 0.2 is 0.30000000000000004
0.1m + 0.2m == 0.3m    // true     decimal is exact
```

> ⚠️ **Never store money in a `double`.** Use `decimal` with the `m` suffix.
> **Never compare two `double`s with `==`.** Compare the difference to a tolerance:
> `Math.Abs(a - b) < 0.000001`

## The other everyday types

```csharp
bool isGameOver = false;    // true or false only
char grade = 'A';           // ONE character, SINGLE quotes
string message = "Hello";   // text, DOUBLE quotes
```

Single and double quotes are **not** interchangeable. `'A'` is a `char`; `"A"` is a `string` of
length 1. Mixing them up is a compile error.

A `char` is really a number — its Unicode code point — so this works:

```csharp
(int)'A'          // 65
(char)('A' + 2)   // 'C'
```

## `var` — let the compiler work it out

```csharp
var count = 10;                  // compiler infers int
var name  = "Ada";               // compiler infers string
var scores = new List<int>();    // infers List<int> - a real saving
```

`var` is **not** Python's dynamic typing. The variable is still strongly typed forever; you have
just saved yourself typing the name twice. These are errors:

```csharp
var mystery;              // nothing to infer from
var x = 5; x = "hello";   // x is an int, permanently
```

## Constants

```csharp
const double Pi = 3.14159;      // must be known at COMPILE time, never changes
const int MaxLives = 3;

readonly DateTime startedAt = DateTime.Now;   // set once at RUN time, then locked
```

## Naming conventions

Professional C# follows these without exception:

| Thing | Style | Example |
|---|---|---|
| Local variable, parameter | `camelCase` | `playerScore` |
| Private field | `_camelCase` | `_balance` |
| Method, property, class, constant | `PascalCase` | `CalculateTotal`, `MaxLives` |
| Interface | `I` + `PascalCase` | `IStorage` |

## Default values

| Type | Default |
|---|---|
| numbers | `0` |
| `bool` | `false` |
| `char` | `'\0'` |
| any reference type | `null` |

Fields get these automatically. **Local variables do not** — the compiler refuses to let you
read one before you assign it. This "definite assignment" rule prevents a whole class of bug.

## Common mistakes

| Mistake | Fix |
|---|---|
| `int price = 19.99;` | `19.99` is a `double`. Use `decimal price = 19.99m;` |
| `char c = "A";` | Double quotes make a string. Use `'A'` |
| Comparing doubles with `==` | Compare the difference to a small tolerance |
| Using `double` for money | Use `decimal` |
| `int total; Console.Write(total);` | Assign it first — locals have no default |
