## The idea

At GCSE you wrote `OUTPUT "Hello"`. C# does the same thing, but it needs some scaffolding
around it, because C# is a **compiled, statically typed** language: the whole program is
checked for mistakes *before* it ever runs.

## The classic program

```csharp
using System;                              // 1

namespace MyFirstApp                       // 2
{
    class Program                          // 3
    {
        static void Main(string[] args)    // 4
        {
            Console.WriteLine("Hello, world!");   // 5
        }
    }
}
```

1. **`using System;`** — `System` is a *namespace* full of ready-made types. `Console` lives
   inside it. This line means you can type `Console` instead of `System.Console`.
2. **`namespace MyFirstApp`** — your own label, so your `Program` class does not clash with
   someone else's `Program` class. Think of it as a surname for your classes.
3. **`class Program`** — a box that holds code and data. In C#, *every* line of code lives
   inside a class or struct. There are no loose statements floating about.
4. **`static void Main(string[] args)`** — the **entry point**. The runtime looks for a method
   called `Main` and starts there.
   - `static` — belongs to the class itself, not to an object
   - `void` — hands nothing back
   - `string[] args` — anything typed after the program name on the command line
5. **The statement** — does the work, and ends with a semicolon.

## The modern short version

Since C# 9 you can skip all the ceremony. If a file contains loose statements, the compiler
wraps them in a class with a `Main` method for you:

```csharp
Console.WriteLine("Hello, world!");
```

That is the whole program. `Program.cs` in this project is written that way — open it and look.

> Both versions compile to **identical** instructions. The short form is shorthand, not a
> different language. Exam papers and older tutorials use the long form, so read both fluently.

## Braces, semicolons and whitespace

C# uses `{ }` to group statements into a **block**, exactly where GCSE pseudocode used words
like `ENDIF`. Unlike Python, **indentation means nothing to the compiler** — but you must still
indent, because unreadable code wastes your own time.

```csharp
if (score > 50)          // no semicolon after the condition
{                        // block opens
    Console.WriteLine("Pass");
    Console.WriteLine("Well done");
}                        // block closes - no semicolon here either
```

## Write and Write­Line

```csharp
Console.Write("No line break. ");
Console.WriteLine("This one ends the line.");
```

`WriteLine` moves to a new line afterwards; `Write` does not.

## What `dotnet run` actually does

1. The compiler (**Roslyn**) reads your `.cs` files and checks them for errors.
2. It translates them into **IL** — Intermediate Language, a CPU-independent bytecode — stored
   in a `.dll` inside `bin/`.
3. The .NET runtime loads that `.dll`, and the **JIT** (Just-In-Time) compiler turns the IL into
   real machine code for *your* processor, the first time each method runs.
4. That machine code runs.

This two-step design is why the same `.dll` runs on Windows, macOS and Linux — exactly the
portability idea from the GCSE *translators* topic. C# gets the error-checking of a compiler
**and** the portability of an interpreter.

## Common mistakes

| Mistake | What happens |
|---|---|
| Missing `;` | Compile error — usually reported on the *next* line |
| `console.WriteLine` | Compile error — C# is **case sensitive** |
| `Console.Writeline` | Compile error — it is `WriteLine`, capital L |
| Missing `}` | Compile error, often pages away from the real problem |
| `if (x > 5);` | **Legal and silently wrong.** The `;` ends the `if`; the block below always runs |

## Exercises

1. Change the message to your own name, then use two `Console.Write` calls instead of
   `WriteLine` and see what happens to the line break.
2. Delete a closing brace on purpose. Read the error message carefully — learning to read
   compiler errors early saves hundreds of hours later.
3. Print a box around your name using `Console.WriteLine` and a row of `=` characters.
4. Rewrite the top-level-statements version as the full `namespace`/`class`/`Main` version, and
   check it still runs.
