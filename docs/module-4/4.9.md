## Paths: always Path.Combine

```csharp
string file = Path.Combine(folder, "scores.txt");   // right separator on every OS

Path.GetFileName(file)                    // "scores.txt"
Path.GetFileNameWithoutExtension(file)    // "scores"
Path.GetExtension(file)                   // ".txt"
Path.GetTempPath()                        // somewhere safe to scratch
```

Never write `folder + "\\file.txt"` by hand: backslash breaks on macOS and Linux, and
forward-slash assumptions break elsewhere. `Path.Combine` uses the machine's separator.

## Whole-file reads and writes

For files that comfortably fit in memory, one call each way:

```csharp
File.WriteAllText(file, "Ada,91\n");        // create or overwrite
File.AppendAllText(file, "Ben,64\n");       // add to the end
File.AppendAllLines(file, ["Cara,78"]);

string all      = File.ReadAllText(file);   // one string
string[] lines  = File.ReadAllLines(file);  // array of lines

File.Exists(file)                            // check before reading
new FileInfo(file).Length                    // size in bytes
```

## The parse-a-file pattern

Reading a simple CSV is Module 3 applied to a file:

```csharp
List<Score> scores = File.ReadAllLines(file)
    .Where(line => !string.IsNullOrWhiteSpace(line))
    .Select(line => line.Split(','))
    .Select(parts => new Score(parts[0], int.Parse(parts[1])))
    .ToList();

scores.Average(s => s.Mark);
scores.MaxBy(s => s.Mark);
```

Lines → split → objects → query. Half of all data-wrangling scripts are this shape.

## Large files: stream, don't load

```csharp
File.ReadAllLines(path)     // string[]              the WHOLE file in memory
File.ReadLines(path)        // IEnumerable<string>   one line at a time, lazily
```

Same loop on the outside; constant memory on the inside — the [3.5](../module-3/3.5.md)
laziness story with a disk behind it. For writing as you go, or fine control, use the stream
classes with `using` ([4.8](4.8.md)):

```csharp
using (StreamWriter writer = new(path))
{
    writer.WriteLine("line one");
}                                            // flushed and closed here

using (StreamReader reader = new(path))
{
    string? first = reader.ReadLine();       // null at end of file
}
```

## Directories

```csharp
Directory.CreateDirectory(sub);              // fine if it already exists
Directory.Exists(sub)
Directory.GetFiles(sub)                      // full paths
Directory.GetFiles(sub, "*.sav")             // with a pattern
Directory.GetDirectories(folder)
Directory.Delete(folder, recursive: true);   // careful with this one
```

## What goes wrong, and handling it

```csharp
try
{
    File.ReadAllText(missing);
}
catch (FileNotFoundException) { ... }        // the file is not there
catch (DirectoryNotFoundException) { ... }   // the FOLDER is not there
catch (UnauthorizedAccessException) { ... }  // permissions
catch (IOException) { ... }                  // locked, disk full, the rest
```

`File.Exists` first avoids the common case; the handlers cover the races and surprises a check
cannot ([4.7](4.7.md)).

## JSON: objects to text and back

Files store text; programs hold objects. **Serialisation** bridges them, and JSON is the
lingua franca:

```csharp
record Player(string Name, int Level, int Points, List<string> Inventory);

Player player = new("Ada", 7, 1250, ["sword", "shield"]);

string json = JsonSerializer.Serialize(player, new JsonSerializerOptions { WriteIndented = true });
File.WriteAllText(savePath, json);
```

```json
{
  "Name": "Ada",
  "Level": 7,
  "Points": 1250,
  "Inventory": ["sword", "shield"]
}
```

And back:

```csharp
Player? loaded = JsonSerializer.Deserialize<Player>(File.ReadAllText(savePath));
```

Records are the perfect partner here: shape-only data, value equality, one line each.

Collections round-trip just as easily:

```csharp
string json = JsonSerializer.Serialize(scoreList);
List<Score>? back = JsonSerializer.Deserialize<List<Score>>(json);
```

## Two traps the lesson demonstrates

**Bad JSON throws.** External data is never trusted data:

```csharp
try { JsonSerializer.Deserialize<Player>(input); }
catch (JsonException) { /* corrupt or not JSON at all */ }
```

And nullability annotations do not survive deserialisation — validate at the boundary
([4.5](4.5.md)).

**Round-trip equality is subtler than it looks.** `loaded == player` is `false` — records
compare members, and `List<string>` compares by *reference* ([2.9](../module-2/2.9.md)). Two
lists with identical contents are still two lists. Compare contents with `SequenceEqual` when
it matters.

## Choosing your method

| Job | Use |
|---|---|
| Small file, want one string | `ReadAllText` |
| Small file, want lines | `ReadAllLines` |
| Big file | `ReadLines` — streams |
| Writing incrementally | `StreamWriter` in a `using` |
| Structured objects | `JsonSerializer` |
| Config / save files | JSON + records |

## Common mistakes

| Mistake | Result |
|---|---|
| Hand-built paths with `\\` | Breaks off-Windows |
| `ReadAllLines` on a huge log | Memory spike — stream instead |
| Forgetting `using` on streams | Locked files ([4.8](4.8.md)) |
| Trusting external JSON | `JsonException`, or nulls where "impossible" |
| Absolute paths hardcoded | Breaks on every other machine |
