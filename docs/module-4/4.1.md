## The idea

Everything you have stored in a variable so far has been *data*. A **delegate** stores a
*method* — which means behaviour can be passed around, swapped and combined like any other
value.

You have already used this constantly without naming it: every lambda you handed to `Where`,
`Sort` and `RemoveAll` in Module 3 travelled inside a delegate.

## Declaring one

```csharp
private delegate int MathOperation(int a, int b);   // the SHAPE: two ints in, int out

MathOperation operation = Add;      // point it at a method - note: no brackets
operation(3, 4)                     // 7 - calls Add

operation = Multiply;               // re-point it
operation(3, 4)                     // 12 - same call site, different behaviour
```

A delegate type is a *shape* — parameter list plus return type. Any method matching the shape
fits, and the method name without brackets is the reference itself.

## Passing behaviour into a method

```csharp
static int Apply(int a, int b, MathOperation operation) => operation(a, b);

Apply(10, 5, Add)                   // 15
Apply(10, 5, Subtract)              // 5
Apply(10, 5, (a, b) => a % b)       // 0 - a lambda fits the same shape
```

One method, infinite behaviours. This is the **Strategy pattern** from
[2.14](../module-2/2.14.md), stripped to its essence.

## The built-in delegates: Func, Action, Predicate

You almost never declare your own delegate type, because three generic families cover nearly
everything:

| Type | Shape | Example |
|---|---|---|
| `Func<int, int, int>` | takes ints, **returns the last type** | `(a, b) => a + b` |
| `Func<string>` | no parameters, returns string | `() => "hi"` |
| `Action<string>` | takes a string, returns **nothing** | `s => Console.WriteLine(s)` |
| `Action` | no parameters, no return | `() => Save()` |
| `Predicate<T>` | takes T, returns bool | `n => n % 2 == 0` |

The rule for `Func`: the **last** type parameter is the return type, everything before it is
parameters.

```csharp
Func<double, double> square = x => x * x;
Action<string> shout = m => Console.WriteLine(m.ToUpperInvariant());
Predicate<int> isEven = n => n % 2 == 0;
```

## Where the framework already uses them

```csharp
list.Find(n => n > 10)              // Predicate<T>
list.RemoveAll(n => n > 10)         // Predicate<T>
items.Where(n => n < 50)            // Func<T, bool>
items.Select(n => n * 2)            // Func<T, TResult>
items.OrderBy(n => n)               // Func<T, TKey>
list.Sort((a, b) => a - b)          // Comparison<T>
```

Module 3 suddenly makes complete sense: LINQ is methods that take delegates.

## Multicast: one call, several methods

`+=` chains methods onto a delegate; invoking it runs them **in order**:

```csharp
Action<string>? pipeline = LogToConsole;
pipeline += LogToFile;
pipeline += m => Console.WriteLine($"[lambda] {m}");

pipeline("system started");         // all three run

pipeline -= LogToFile;              // remove one
pipeline?.Invoke("second message"); // two run
```

Two details that matter:

- Removing the **last** method leaves the delegate `null` — hence `?.Invoke`.
- For a `Func`, only the *last* method's return value survives; the others are discarded.
  Multicast is really for `Action`-shaped things — it is the machinery under events
  ([4.3](4.3.md)).

## Returning a function from a function

```csharp
static Func<int, int> Multiplier(int factor) => n => n * factor;

Func<int, int> triple = Multiplier(3);
triple(7)                           // 21
```

`Multiplier` *builds* a new function. The returned lambda remembers `factor` — that memory is a
closure, the subject of [4.2](4.2.md).

## Common mistakes

| Mistake | Result |
|---|---|
| `operation = Add();` | Calls Add and assigns its **result** — drop the brackets |
| Invoking a possibly-null delegate | `NullReferenceException` — use `?.Invoke` |
| Multicast `Func` expecting all results | Only the last survives |
| Declaring a delegate type when `Func` fits | Extra noise — use the built-ins |
