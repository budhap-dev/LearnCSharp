# 4.4 — Extension methods: adding methods to types you do not own

> **Run it:** `dotnet run --project src/LearnCSharp.Lessons -- 4.4`
> **Code:** [`L04_ExtensionMethods.cs`](../../src/LearnCSharp.Lessons/Lessons/M4_Advanced/L04_ExtensionMethods.cs)

---

## The idea

`string` is sealed ([2.5](../module-2/2.5.md)) and lives inside .NET — you cannot inherit it or
edit it. Yet this works:

```csharp
"the quick brown fox".WordCount()     // 4
```

because of an **extension method**:

```csharp
public static class StringExtensions
{
    public static int WordCount(this string text) =>
        text.Split(' ', StringSplitOptions.RemoveEmptyEntries).Length;
}
```

The `this` on the first parameter is the whole feature: it lets the method be *called as if it
belonged to* `string`.

## The rules

1. The containing class must be `static`.
2. The method must be `static`.
3. The first parameter carries `this` — that is the type being extended.
4. Callers need a `using` for the namespace the extension lives in.

And the honest truth underneath: **it is just a static method**. These two lines are
identical after compilation:

```csharp
sentence.WordCount();
StringExtensions.WordCount(sentence);
```

The extension syntax is sugar. That also means extensions can only touch the type's **public**
surface — no access to private state, because none was ever granted.

## Extending anything

```csharp
public static bool IsPrime(this int n) { ... }
7.IsPrime()                                   // true

public static string Truncate(this string s, int max) =>
    s.Length <= max ? s : s[..max] + "...";

public static double Median(this IEnumerable<int> source) { ... }
scores.Median()
```

Extensions chain like any other method:

```csharp
"  hello world  ".Trim().ToTitleCase().Truncate(8)
```

## This is exactly how LINQ works

The revelation of this lesson: `Where`, `Select`, `OrderBy` — every operator from Module 3 —
are extension methods on `IEnumerable<T>`, declared in the static class
`System.Linq.Enumerable`:

```csharp
numbers.Where(n => n > 10)                    // extension syntax
Enumerable.Where(numbers, n => n > 10)        // what it really is
```

That is why LINQ needs `using System.Linq;`, and why it works on arrays, lists, and your own
`Playlist` from [3.5](../module-3/3.5.md) alike: one interface, extended once, everywhere.

## Null and extensions — a genuine oddity

A real method call on `null` throws before the method starts. An extension is a static call,
so the null **arrives as the argument** and the method can handle it:

```csharp
public static bool IsNullOrBlank(this string? text) => string.IsNullOrWhiteSpace(text);

string? nothing = null;
nothing.IsNullOrBlank()       // true - no exception!
```

Used sparingly this is lovely (`IsNullOrBlank` reads perfectly); overused it makes code lie
about what can crash.

## Resolution rules worth knowing

- **A real instance method always wins.** If the type has its own `WordCount`, yours is
  ignored — silently.
- Extensions are found through `using` directives; no `using`, no method, and the compiler
  error ("no definition for...") does not mention extensions, which catches people.

## When to write one

| Good | Bad |
|---|---|
| Fluent helpers on framework types (`Truncate`, `IsNullOrBlank`) | Anything needing private access — put it *in* the class |
| Utilities on interfaces so every implementer benefits | Core domain logic — that belongs to the domain class |
| Making an API you cannot change nicer to call | A grab-bag `Extensions` class of unrelated methods |

The interface case is the strongest: extend `IEnumerable<T>` once and every collection ever
written gains the method — which is precisely LINQ's trick.

## Common mistakes

| Mistake | Result |
|---|---|
| Forgetting the `using` | "No definition for X" — confusing error |
| Non-static class or method | Compile error on `this` |
| Shadowing a real method | The real one wins; yours never runs |
| Extending everything reflexively | API sprawl — sometimes a plain helper is clearer |

## Exercises

1. Write `ToTitleCase(this string)` and `Reverse(this string)`.
2. Write `Median(this IEnumerable<int>)` handling odd and even counts, throwing on empty.
3. Write `Shuffle<T>(this IList<T>, Random)` — an in-place Fisher–Yates shuffle.
4. Call one of your extensions both ways (extension syntax and static syntax) to prove they
