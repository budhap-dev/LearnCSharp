## Tuples: grouping values without a type

```csharp
(string Name, int Age) named = ("Ada", 36);
named.Name                 // "Ada"
named.Age                  // 36
```

A tuple bundles a few values with **no class declaration**. Its natural home is returning
several things from a method:

```csharp
static (int min, int max, double average) Analyse(int[] values) =>
    (values.Min(), values.Max(), values.Average());

var stats = Analyse(data);
stats.min; stats.max;

// or deconstruct straight into locals:
(int low, int high, _) = Analyse(data);        // _ discards what you don't want
```

Compare with `out` parameters from [1.9](../module-1/1.9.md) — tuples are the modern,
readable version of the same idea.

### Tuples compare by value

```csharp
(1, "x") == (1, "x")       // true
```

### The swap idiom

```csharp
(a, b) = (b, a);           // no temp variable
```

You have seen this in the sorting lessons — it *is* tuple deconstruction.

### Tuple or record?

| | Tuple | Record ([2.9](../module-2/2.9.md)) |
|---|---|---|
| Declaration | none | one line |
| Member names | per-usage, easily inconsistent | fixed and documented |
| Use for | private helpers, quick pairs | anything public or long-lived |

Rule of thumb: a tuple crossing a public API boundary usually wants to be a record.

## Deconstructing your own types

Any type gains `(a, b, c) = obj` by providing a `Deconstruct` method:

```csharp
public void Deconstruct(out double x, out double y, out double z)
{
    x = X; y = Y; z = Z;
}
```

Positional records generate this automatically — another line in the [2.9](../module-2/2.9.md)
bargain.

## Pattern matching, the full toolkit

[1.5](../module-1/1.5.md) introduced type and range patterns. Here is the rest of the family.

### Switching on a tuple

```csharp
static string Judge(string p1, string p2) => (p1, p2) switch
{
    ("rock", "scissors") or ("paper", "rock") or ("scissors", "paper") => "player 1 wins",
    (var x, var y) when x == y => "draw",
    _ => "player 2 wins",
};
```

Rock-paper-scissors as a table of cases — try writing that with ifs and compare.

### Property patterns

Match on an object's properties, no casting, no temp variables:

```csharp
static string Postage(Order order) => order switch
{
    { Country: "UK", Amount: > 50 }      => "free UK delivery",
    { Country: "UK" }                    => "3.99 UK delivery",
    { Country: not "UK", Amount: > 100 } => "15.00 international",
    _                                    => "9.99 international",
};
```

This reads like the pricing table a human would write on paper — which is the point.

### List patterns (C# 11)

```csharp
static string Describe(int[] values) => values switch
{
    []                        => "empty",
    [var only]                => $"one item: {only}",
    [var first, var second]   => $"two: {first} and {second}",
    [1, ..]                   => "starts with 1",
    [.., var last]            => $"ends with {last}",
};
```

`..` is a *slice* — "any number of items here".

### Positional patterns on records

Records deconstruct, so they match positionally, and `when` adds guards:

```csharp
static string Classify(Shape shape) => shape switch
{
    Circle(var r) when r > 5    => "a big circle",
    Circle(var r)               => $"a circle of radius {r}",
    Rect(var w, var h) when w == h => $"a square of side {w}",
    Rect(var w, var h)          => $"a {w} by {h} rectangle",
    _                           => "unknown",
};
```

Combined with a record hierarchy (`abstract record Shape; record Circle(...) : Shape`), this
is C#'s version of functional-style data modelling: dumb data + one switch that handles every
shape, with the compiler warning when a case is missing.

## When patterns beat polymorphism — and when not

| Situation | Prefer |
|---|---|
| Behaviour belongs to the type, types added often | virtual methods ([2.6](../module-2/2.6.md)) |
| Logic spans several values/shapes, cases added often | pattern switch |
| External data you cannot add methods to | pattern switch |

They are complementary tools, not rivals.

## Common mistakes

| Mistake | Result |
|---|---|
| Huge tuples (`(a,b,c,d,e,f)`) | Unreadable — make a record |
| Same tuple shape, different names in different places | Confusion — make a record |
| Forgetting `_` in a switch expression | `SwitchExpressionException` at runtime |
| `when` guard doing heavy work | Hidden cost per case tested |

## Exercises

1. Write `MinMax(int[])` returning a named tuple, and deconstruct it at the call site.
2. Implement fizz-buzz with a single switch on `(n % 3, n % 5)`.
3. Write a `Postage`-style rules table for cinema ticket pricing (age, day, 3D).
4. Model `abstract record Journey` with `Walk(km)`, `Bus(stops)`, `Train(km, changes)` and
   write one switch computing cost. Add a case and note the compiler's help.
5. With list patterns: match a command array like `["move", var direction]` /
   `["take", .. var items]`.
