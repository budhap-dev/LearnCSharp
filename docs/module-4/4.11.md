## The idea

**Reflection** is a program inspecting — and even driving — itself while it runs: listing a
type's members, reading values by name, creating objects from strings.

It sounds exotic. It is the machinery under half the tools you use: JSON serialisation
([4.9](4.9.md)) reads your properties by reflection; test runners find `[Test]` methods by
reflection; **this course's own menu finds its 57 lessons by reflection**.

## Inspecting a type

```csharp
Type type = typeof(Monster);          // from the type name
goblin.GetType()                      // from an object - its REAL runtime type

type.Name                             // "Monster"
type.BaseType?.Name                   // its parent
type.GetProperties()                  // every property, as PropertyInfo objects
type.GetMethods()                     // every method
```

A `Type` object describes a type the way an object describes a thing — metadata as data.

## Reading values by name

```csharp
foreach (PropertyInfo property in type.GetProperties())
    Console.WriteLine($"{property.Name} = {property.GetValue(goblin)}");
```

No compile-time knowledge of `Monster` needed — this loop prints *any* object's properties.
That is precisely how a serialiser works.

## Creating and invoking dynamically

```csharp
object? created = Activator.CreateInstance(typeof(Monster), "Dragon", 500, 90);

MethodInfo? attack = type.GetMethod(nameof(Monster.Attack));
attack?.Invoke(goblin, [10]);         // goblin.Attack(10), spelled at runtime
```

`nameof` matters here: `GetMethod("Attack")` with a string survives a rename as a runtime
failure; `nameof(Monster.Attack)` fails at compile time instead.

## Attributes: metadata you attach

An **attribute** is a note pinned to code — stored in the compiled assembly, readable later by
reflection:

```csharp
[Obsolete("Use NewMethod instead")]     // built-in: compiler warns callers
[Flags]                                 // built-in: changes enum behaviour (2.8)
```

Defining your own:

```csharp
[AttributeUsage(AttributeTargets.Property)]
public sealed class ColumnAttribute : Attribute
{
    public ColumnAttribute(string name, int order) { Name = name; Order = order; }
    public string Name { get; }
    public int Order { get; }
}
```

Using it:

```csharp
public class SaveGame
{
    [Column("player", 1)] public string PlayerName { get; set; } = "";
    [Column("lvl", 2)]    public int Level { get; set; }
    [Column("score", 3)]  public int Score { get; set; }

    public string TempCacheValue { get; set; } = "";     // no attribute - not saved
}
```

The `Attribute` suffix is dropped at the use site; `[Column(...)]` means `ColumnAttribute`.

## The payoff: attributes + reflection = generic tools

```csharp
static string ToCsvRow<T>(T item) =>
    string.Join(",", typeof(T).GetProperties()
        .Select(p => new { p, attr = p.GetCustomAttribute<ColumnAttribute>() })
        .Where(x => x.attr is not null)
        .OrderBy(x => x.attr!.Order)
        .Select(x => x.p.GetValue(item)?.ToString() ?? ""));
```

`ToCsvRow(save)` → `"Ada,7,1250"` — for **any** class marked with `[Column]`, written once.
The class declares *what* to save; the tool discovers *how*. Serialisers, ORMs and test
frameworks are this pattern, scaled up.

## How this course eats its own cooking

`LessonRegistry` scans the assembly for every class implementing `ILesson`, instantiates each
with `Activator.CreateInstance`, and sorts them by id. Adding lesson 58 to the menu requires
writing lesson 58 — and nothing else. The website's whole content pipeline starts from that
one reflective scan.

## The trade-offs — respect them

| | |
|---|---|
| **Slow** | ~10–100× a direct call. Cache `MethodInfo`/`PropertyInfo` if used repeatedly |
| **Unsafe** | typos become runtime errors; refactoring tools cannot see string names |
| **Opaque** | "find all usages" misses reflective calls |

> **Advice:** reflection is wonderful for *frameworks* — code that must handle types it has
> never seen. In everyday application code, if you know the type, call it directly. Reaching
> for reflection to dodge a design problem creates two problems.

## Common mistakes

| Mistake | Result |
|---|---|
| `GetMethod("Atack")` | null at runtime, no compile error — use `nameof` |
| Reflection in a hot loop, uncached | Dramatic slowdown |
| Forgetting `[AttributeUsage]` | Attribute lands where it should not |
| Reading attributes but never null-checking | Members without the attribute crash you |
