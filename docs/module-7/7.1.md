## The brief

The computer picks a number from 1 to 100; the player guesses; each guess earns "too low",
"too high" or "correct". Small enough to finish, rich enough to show the single most important
habit in this module: **keeping the rules separate from the console**.

| Draws on | For |
|---|---|
| [1.6](../module-1/1.6.md) loops · [1.3](../module-1/1.3.md) validation | the game loop |
| [2.2](../module-2/2.2.md)–[2.4](../module-2/2.4.md) classes, encapsulation | the game state |
| [2.8](../module-2/2.8.md) enums | the guess result |
| [5.2](../module-5/5.2.md) binary search | the optimal strategy |

## The design decision that matters

All the rules live in a class with **no `Console` calls anywhere in it**:

```csharp
public enum GuessResult { TooLow, TooHigh, Correct, OutOfRange }

public class GuessingGame
{
    private readonly int _secret;

    public int Attempts { get; private set; }
    public bool IsOver { get; private set; }

    public GuessResult Guess(int guess)
    {
        if (IsOver) throw new InvalidOperationException("The game has already finished.");
        if (guess < 1 || guess > _maximum) return GuessResult.OutOfRange;  // costs no attempt

        Attempts++;
        if (guess == _secret) { IsOver = true; return GuessResult.Correct; }
        return guess < _secret ? GuessResult.TooLow : GuessResult.TooHigh;
    }
}
```

Why this split pays, immediately:

- the same class works in a console app, a web page or a test;
- the rules are enforced *inside* — a finished game refuses more guesses
  ([2.4](../module-2/2.4.md)'s encapsulation, [4.7](../module-4/4.7.md)'s "wrong time" exception);
- an out-of-range guess returns a value instead of throwing, because bad input is *expected*
  ([4.7](../module-4/4.7.md)'s decision table);
- **the computer can play it** — which is where it gets interesting.

## The computer plays perfectly

"Too low / too high" is exactly the information binary search needs ([5.2](../module-5/5.2.md)):

```csharp
int low = 1, high = maximum;
while (!game.IsOver)
{
    int guess = low + (high - low) / 2;        // always split the range
    GuessResult result = game.Guess(guess);

    if (result == GuessResult.TooLow) low = guess + 1;
    else if (result == GuessResult.TooHigh) high = guess - 1;
}
```

The lesson proves the theory empirically, playing **every** secret from 1 to 100:

| Strategy | Worst case | Average |
|---|---|---|
| guess 1, 2, 3… (linear) | 100 attempts | 50.5 |
| binary search | **7** attempts | ~5.8 |

⌈log₂ 100⌉ = 7 — and a range of a **million** would need only 20. If a friend claims they can
always win "guess my number 1–1000" in ten goes, they are telling the truth.

## The interactive loop

The console front end is the thin part — the `while (true)` + `TryParse` pattern from
[1.3](../module-1/1.3.md), a `switch` on the enum from [1.5](../module-1/1.5.md), and every
rule already handled by the class.

## Extend it yourself

1. Difficulty levels: range and attempt limit change together.
2. High-score table saved as JSON ([4.9](../module-4/4.9.md)).
3. Reverse mode: *you* think of the number, the computer guesses — you already wrote its brain.
4. "Warmer / colder" feedback based on distance from the previous guess.
