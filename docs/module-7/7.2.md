## The brief

A teacher records marks per student per subject, and needs: individual reports, class
statistics, per-subject breakdowns, rankings and search. This is the most *realistic* project
in the course — nearly every business system is this shape: entities, rules, and reports over
them.

## Two classes, two jobs

**`Student`** owns its marks and everything computable from them:

```csharp
public class Student
{
    private readonly Dictionary<string, int> _marks = new();

    public IReadOnlyDictionary<string, int> Marks => _marks;      // look, don't touch

    public double Average => _marks.Count == 0 ? 0 : _marks.Values.Average();
    public char Grade => GradeFor(Average);

    internal void SetMark(string subject, int mark)
    {
        if (mark is < 0 or > 100)
            throw new ArgumentOutOfRangeException(nameof(mark), "Marks run from 0 to 100.");
        _marks[subject] = mark;
    }
}
```

**`SchoolRegister`** owns the collection and the rules that need to see *everyone* — duplicate
ids, unknown students, class-wide statistics. The same where-does-the-rule-live question as the
library workshop ([2.15](../module-2/2.15.md)): a rule lives with the data it needs.

Note `IReadOnlyDictionary`: outsiders can read marks but only the register can write them,
so no mark ever dodges validation ([2.4](../module-2/2.4.md)'s read-only collections).

## Every report is one query

The pay-off for Module 3. Each teacher request translates line-for-line:

```csharp
// "rank the class"
_students.Values.OrderByDescending(s => s.Average)

// "who needs support?"
_students.Values.Where(s => s.Average < 60)

// "how is each subject doing?" - flatten, group the other way, summarise (3.7)
_students.Values
    .SelectMany(s => s.Marks, (student, mark) => new { mark.Key, mark.Value })
    .GroupBy(entry => entry.Key)
    .Select(g => new SubjectStats(g.Key, g.Average(e => e.Value),
                                  g.Max(e => e.Value), g.Min(e => e.Value),
                                  g.Count(e => e.Value >= 50)));
```

That last one is the [3.7](../module-3/3.7.md) `SelectMany`-then-`GroupBy` pattern earning its
keep: marks live *inside* students, but the subject report needs them grouped *across*
students.

## Validation refuses loudly

```csharp
register.RecordMark(1, "Maths", 150);   // ArgumentOutOfRangeException
register.RecordMark(99, "Maths", 50);   // KeyNotFoundException - no such student
register.Enrol(duplicate);              // InvalidOperationException
```

Each is the caller's bug, so each **throws** — the [4.7](../module-4/4.7.md) decision table
applied. Contrast `Find(id)`, which returns `null`, because "not found" is a normal outcome.
