## The brief

A to-do list whose tasks **survive the program closing** — add, complete, delete, query, all
persisted as JSON. The last project, and the one shaped most like professional code: a
miniature of the layered architecture behind almost every real application.

| Draws on | For |
|---|---|
| [2.9](../module-2/2.9.md) records | `TodoItem`, immutable |
| [2.7](../module-2/2.7.md) interfaces · [2.13](../module-2/2.13.md) D | swappable storage |
| [2.14](../module-2/2.14.md) | this *is* the Repository pattern |
| [4.9](../module-4/4.9.md) JSON · [4.10](../module-4/4.10.md) async | the persistence itself |

## The architecture

```
TodoService          the rules: ids, validation, completion
    |
ITodoStore           the contract: LoadAsync / SaveAsync
    |
JsonTodoStore        one implementation - a file on disk
InMemoryTodoStore    another - for tests
```

```csharp
public interface ITodoStore
{
    Task<List<TodoItem>> LoadAsync();
    Task SaveAsync(List<TodoItem> items);
}
```

The service depends on **the interface, never the file** — [2.13](../module-2/2.13.md)'s
dependency inversion as working code. The payoff is the last section of the lesson: the same
service runs against an in-memory fake, so its logic is testable with no disk, no cleanup, no
async ceremony beyond `Task.FromResult`. Swap in a database store later and the service does
not change by one line.

## Records make the domain honest

```csharp
public record TodoItem(int Id, string Title, Priority Priority, DateOnly? Due, bool IsDone);
```

Completing an item is not mutation — it is a copy with one change
([2.9](../module-2/2.9.md)'s `with`):

```csharp
items[index] = items[index] with { IsDone = true };
```

`DateOnly?` uses nullability to *mean* something — "no deadline" — the
[4.5](../module-4/4.5.md) rule that `?` should carry information, not laziness.

## Defensive loading

External data is never trusted data ([4.9](../module-4/4.9.md)):

```csharp
public async Task<List<TodoItem>> LoadAsync()
{
    if (!File.Exists(_path)) return [];          // first run is not an error

    try
    {
        string json = await File.ReadAllTextAsync(_path);
        return JsonSerializer.Deserialize<List<TodoItem>>(json) ?? [];
    }
    catch (JsonException)
    {
        return [];                               // corrupt file must not kill the app at startup
    }
}
```

A missing file means "nothing saved yet"; a corrupt one degrades to empty rather than
crashing. (A real app would also back the corrupt file up — extension 5.)

## Queries, sorted the way a human wants

```csharp
items.OrderBy(i => i.IsDone)                        // outstanding first
     .ThenByDescending(i => i.Priority)             // most urgent
     .ThenBy(i => i.Due ?? DateOnly.MaxValue)       // soonest deadline; no deadline last
```

That `?? DateOnly.MaxValue` is a small trick worth stealing: it makes null sort *last*
without a special case.

## Extend it yourself

1. Tags, and filtering by them.
2. A full menu loop: add / list / done / delete / quit.
3. Overdue tasks highlighted in red (`Console.ForegroundColor`).
4. Swap `JsonTodoStore` for a CSV store — count how many files change. That number is the
   architecture's grade.
5. On `JsonException`, rename the corrupt file to `.bak` before returning empty.
