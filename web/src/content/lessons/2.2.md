## The big shift

So far your programs have been *a list of instructions operating on loose variables*. Object-
oriented programming reorganises them into *objects that own their own data and know how to
behave*.

- A **class** is a blueprint — it describes what something is and can do.
- An **object** (an *instance*) is one thing built from that blueprint.

One `Book` class; ten thousand `Book` objects, each with its own title.

## A minimal class

```csharp
public class Book
{
    private int _pagesRead;                  // field: hidden internal state

    public string Title { get; }             // property: get only
    public string Author { get; set; }
    public int Pages { get; set; }

    public Book(string title, string author, int pages)   // constructor
    {
        Title = title;
        Author = author;
        Pages = pages;
    }

    public void Read(int pages)              // method: behaviour
    {
        _pagesRead = Math.Min(_pagesRead + pages, Pages);
    }

    public string Progress() => $"{_pagesRead}/{Pages} pages";
}
```

```csharp
Book hobbit = new Book("The Hobbit", "Tolkien", 310);
hobbit.Read(50);
Console.WriteLine(hobbit.Progress());     // "50/310 pages"
```

## The parts

| Part | What it is |
|---|---|
| **Field** | A variable belonging to the object. Usually `private`, named `_camelCase`. |
| **Property** | A controlled way to expose a value. `public`, `PascalCase`. |
| **Constructor** | Runs when you write `new`. Same name as the class, no return type. Its job is to leave the object in a **valid** state. |
| **Method** | Something the object can do. |

## Auto-properties

```csharp
public string Author { get; set; }
```

The compiler writes the hidden backing field for you. Variants:

```csharp
public string Title { get; }               // set only in the constructor
public string Name  { get; private set; }  // anyone reads, only this class writes
public int Port     { get; init; }         // set only while constructing
public string Id    { get; } = "unset";    // with a default
```

## Constructors

You can have several, as long as the parameters differ. Chain them with `: this(...)` so the
real work lives in one place:

```csharp
public Book(string title, string author, int pages) { ... }

public Book(string title) : this(title, "Unknown", 0) { }
```

If you write **no** constructor, C# gives you a free parameterless one. Write any constructor
and that freebie disappears.

## Object initialiser syntax

Sets public properties **after** the constructor runs — handy when most values are optional:

```csharp
Book note = new Book("Notebook") { Author = "Me", Pages = 100 };
```

## `this`

`this` means "the object this method was called on". Optional, unless a parameter name hides a
field:

```csharp
public Book(string title)
{
    this.title = title;      // 'this.' disambiguates
}
```

## Objects are reference types

```csharp
Book alias = hobbit;      // copies the ARROW, not the book
alias.Read(100);          // hobbit changed too - they are the same object
ReferenceEquals(alias, hobbit)   // true
```

This is the single most important consequence of classes being reference types. See
[2.8](2.8.md).

## null

A reference variable can point at **nothing**:

```csharp
Book? missing = null;
missing?.Title            // null - safe
missing.Title             // NullReferenceException
missing is null           // true
```

## static members

A `static` member belongs to the **class**, shared by every object:

```csharp
public static int Count { get; private set; }   // one counter for all Books
```

More in [2.11](2.11.md).

## Designing a class — questions to ask

1. **What is it?** One clear thing. `Book`, `BankAccount`, `Player` — not `Manager` or `Data`.
2. **What does it know?** Those become fields and properties.
3. **What can it do?** Those become methods.
4. **What must always be true?** (A balance is never negative; pages read never exceeds pages.)
   The constructor establishes it and the methods preserve it.

## Common mistakes

| Mistake | Fix |
|---|---|
| `Book b;` then `b.Read(10)` | You declared a variable but never created an object — use `new` |
| Making every field `public` | Keep state private — [2.4](2.4.md) |
| A constructor that leaves the object half-built | Set everything a valid object needs |
| Expecting `b2 = b1` to copy | It copies the reference |
| Comparing objects with `==` expecting content equality | See [2.8](2.8.md) |

## Exercises

1. Write a `Rectangle` class with `Width`, `Height`, an `Area()` method and a `Perimeter()`
   property. Create three and print their details.
2. Write a `BankAccount` class with a private balance, `Deposit`, `Withdraw` and a read-only
   `Balance`. Refuse invalid amounts.
3. Write a `Dice` class with a configurable number of sides and a `Roll()` method. Roll 1000
   times and check the distribution.
4. Add a static counter to any of the above that tracks how many objects were created.
