## Why methods exist

This is the GCSE **subroutine** topic, and the reasons are the same:

- **Decomposition** — split one big problem into small solvable ones
- **Reuse** — write once, call a hundred times
- **Naming** — `AreaOfCircle(r)` explains itself; `3.14159 * r * r` does not
- **Testing** — a small method with a clear input and output is easy to test

## Anatomy

```csharp
private static double AreaOfCircle(double radius)
{
    return Math.PI * radius * radius;
}
//  |       |        |         |         |
//  |       |        |         |         +-- parameter (type + name)
//  |       |        |         +------------ method name (PascalCase)
//  |       |        +---------------------- return type
//  |       +------------------------------- static: belongs to the class, not an object
//  +--------------------------------------- access modifier
```

GCSE called a subroutine that returns a value a **function**, and one that does not a
**procedure**. C# uses one word — *method* — and `void` means "procedure".

An **expression-bodied** method is shorthand when the body is one expression:

```csharp
private static double AreaOfCircle(double radius) => Math.PI * radius * radius;
```

## Parameters are passed by value

For value types, the method gets its **own copy**. Changing it inside does not affect the caller:

```csharp
static void TryToDouble(int value) => value *= 2;

int number = 10;
TryToDouble(number);      // number is still 10
```

For **reference types** the copy is a copy of the *arrow*. Both point at the same object, so
changes to the **contents** are visible outside — but reassigning the parameter is not:

```csharp
static void ModifyContents(int[] a) => a[0] = 99;      // caller SEES this
static void ReplaceEntirely(int[] a) => a = [7, 7, 7]; // caller does NOT
```

## `ref` — pass the variable itself

```csharp
static void Swap(ref int first, ref int second) => (first, second) = (second, first);

Swap(ref a, ref b);     // 'ref' required at the CALL site too
```

The variable must be assigned before the call.

## `out` — return more than one value

Like `ref`, but the caller need not assign anything first, and the method **must** assign it
before returning. This is the `TryParse` pattern:

```csharp
static bool TryDivide(int n, int d, out int whole, out int remainder)
{
    whole = 0;
    remainder = 0;
    if (d == 0) return false;      // out params must be set on EVERY path

    whole = n / d;
    remainder = n % d;
    return true;
}

if (TryDivide(17, 5, out int w, out int r))  Console.WriteLine($"{w} r {r}");
if (!TryDivide(17, 0, out _, out _))         Console.WriteLine("no");   // _ discards
```

> In modern C#, returning a **tuple** is often nicer than two `out` parameters —
> see [4.6](../module-4/4.6.md).

## Optional and named arguments

```csharp
static string Greet(string name, string greeting = "Hello", string punctuation = "!")
    => $"{greeting}, {name}{punctuation}";

Greet("Ada");                        // "Hello, Ada!"
Greet("Ada", "Hi");                  // "Hi, Ada!"
Greet("Ada", punctuation: "?");      // skip the middle one by naming
```

Named arguments make call sites readable: compare `CreateWindow(true, false, true)` with
`CreateWindow(visible: true, modal: false, resizable: true)`.

Optional parameters must come **after** all required ones.

## Overloading

Reuse a method name as long as the **parameter list** differs. The compiler picks the right one:

```csharp
static int    Add(int x, int y)          => x + y;
static double Add(double x, double y)    => x + y;
static int    Add(int x, int y, int z)   => x + y + z;
static string Add(string x, string y)    => x + y;
```

> The **return type alone is not enough** to tell two overloads apart. Two methods differing
> only in return type is a compile error.

## `params` — any number of arguments

```csharp
static int Total(params int[] numbers)
{
    int sum = 0;
    foreach (int n in numbers) sum += n;
    return sum;
}

Total();                  // 0
Total(1, 2, 3, 4, 5);     // 15
Total(new[] { 10, 20 });  // 30 - an array works too
```

Must be the **last** parameter, and there can be only one. `Console.WriteLine` uses it.

## Recursion

A method that calls itself. Needs a **base case** and a step that moves towards it:

```csharp
static long Factorial(int n)
{
    if (n <= 1) return 1;             // base case
    return n * Factorial(n - 1);      // recursive case, n gets smaller
}
```

Forget the base case and you get `StackOverflowException` — which, unlike most exceptions,
**cannot be caught**. The program simply dies. Much more in [5.4](../module-5/5.4.md).

## Local functions

A method declared inside another method, for a helper only that method needs:

```csharp
void ProcessOrder()
{
    double net = 100;
    Console.WriteLine(WithVat(net));

    double WithVat(double amount) => amount * 1.2;   // local function
}
```

## Good method design

- **One job.** If the name needs "And" in it, split it.
- **Short.** If it does not fit on one screen, it is doing too much.
- **Few parameters.** More than about four suggests they belong together in a class.
- **Name it as a verb phrase:** `CalculateTotal`, `IsValid`, `LoadPlayer`.
- **Prefer returning a value** to changing something elsewhere — far easier to test.

## Common mistakes

| Mistake | Fix |
|---|---|
| Forgetting `return` on some path | Compile error: "not all code paths return a value" |
| Expecting a value-type parameter to change | Use `ref`, or return the new value |
| `Swap(a, b)` without `ref` at the call | `ref` is needed in both places |
| Overloads differing only by return type | Not allowed — change the parameters or the name |
| Recursion with no base case | `StackOverflowException` |

## Exercises

1. Write `bool IsPrime(int n)` and use it to print all primes below 100.
2. Write a method taking an `int[]` and returning both the min and the max using `out`.
3. Write overloads of `Area` for a circle, a rectangle and a triangle.
4. Write `int Fibonacci(int n)` recursively, then iteratively. Time both for n = 35.
5. Refactor one of your earlier long programs so `Main` is under 10 lines and every step is a
   named method.
