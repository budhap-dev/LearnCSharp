## From pseudocode to C#

```
IF score > 70 THEN              if (score > 70)
    OUTPUT "A"                  {
ELSE IF score > 50 THEN             Console.WriteLine("A");
    OUTPUT "B"                  }
ELSE                            else if (score > 50)
    OUTPUT "C"                  {
ENDIF                               Console.WriteLine("B");
                                }
                                else
                                {
                                    Console.WriteLine("C");
                                }
```

**Order matters.** Conditions are tested top to bottom and the **first true one wins**; the rest
are skipped. Put `score > 50` first and a score of 85 prints `B`.

## Always use braces

Braces are optional for a single statement — and leaving them out is how bugs get in:

```csharp
if (raining)
    TakeUmbrella();
    WearBoots();     // NOT part of the if! It always runs.
```

The indentation lies. Only the first statement belongs to the `if`. **Always write braces.**

## Flattening nested ifs

```csharp
// Hard to read
if (user != null)
    if (user.IsActive)
        if (user.Age >= 18)
            Allow();

// Better: combine with &&
if (user != null && user.IsActive && user.Age >= 18)
    Allow();

// Best for long methods: guard clauses - handle bad cases first and leave early
if (user == null) return;
if (!user.IsActive) return;
if (user.Age < 18) return;
Allow();
```

## The switch statement

When you compare **one value against many fixed options**, `switch` beats a ladder of else-ifs:

```csharp
switch (dayNumber)
{
    case 1:
        Console.WriteLine("Monday");
        break;
    case 6:
    case 7:                          // two labels sharing one body IS allowed
        Console.WriteLine("Weekend");
        break;
    default:
        Console.WriteLine("Some other day");
        break;
}
```

Each case must end with `break` (or `return`). Unlike C and Java, **C# will not let you fall
through by accident** — it is a compile error.

## The switch expression — modern C#

Since C# 8 a switch can be an *expression* that produces a value:

```csharp
string name = dayNumber switch
{
    1 => "Monday",
    2 => "Tuesday",
    6 or 7 => "Weekend",
    _ => "Unknown",              // _ is the discard / catch-all arm
};
```

No `case`, no `break`, an arrow per arm, and a comma between them. Shorter, and the compiler
warns you if you have missed a possible value.

## Pattern matching

The arms do not have to be constants.

### Range patterns

```csharp
string band = temperature switch
{
    < 0            => "Freezing",
    >= 0 and < 10  => "Cold",
    >= 10 and < 20 => "Mild",
    >= 20 and < 30 => "Warm",
    _              => "Hot",
};
```

### Type patterns

```csharp
static string Describe(object? value) => value switch
{
    null               => "nothing at all",
    int i when i > 100 => $"a big int: {i}",     // 'when' adds an extra condition
    int i              => $"an int: {i}",
    string s           => $"a string of {s.Length} chars",
    Array a            => $"an array of {a.Length} items",
    _                  => "something else",
};
```

Note how `int i` both **tests** the type and **gives you a typed variable** in one step.

## The `is` operator

```csharp
if (boxed is int number && number > 10)      // test and capture together
    Console.WriteLine(number);

boxed is not string          // negated pattern
boxed is > 40 and < 50       // relational + logical
value is null                // the clearest null test
```

## Which should I use?

| Situation | Use |
|---|---|
| One condition, two outcomes | `if` / `else` |
| One simple value from a condition | ternary `?:` |
| One value tested against many constants | `switch` expression |
| Ranges, types, or destructuring | `switch` expression with patterns |
| Several unrelated conditions | `if` / `else if` chain |

## Common mistakes

| Mistake | What happens |
|---|---|
| `if (x > 5);` | The `;` ends the `if`. The block below always runs |
| Conditions in the wrong order | A later, more specific case is never reached |
| Missing `break` in a `switch` statement | Compile error (a good thing) |
| `if (name == "ada")` for user input | Case sensitive — use `Equals(..., StringComparison.OrdinalIgnoreCase)` |
| Forgetting `_` in a switch expression | Runtime `SwitchExpressionException` if nothing matches |

## Exercises

1. Rewrite the grade ladder as a switch expression using range patterns.
2. Write a rock-paper-scissors judge using a switch expression on a tuple:
   `(p1, p2) switch { ("rock", "scissors") => "P1 wins", ... }`
3. Write `string Fizz(int n)` returning `"Fizz"`, `"Buzz"`, `"FizzBuzz"` or the number — first
   with `if`, then as a switch expression on `(n % 3, n % 5)`.
4. Write a method that takes an `object?` and describes it, covering `null`, `int`, `string`,
   `bool` and anything else.
